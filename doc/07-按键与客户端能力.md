# 07 按键与客户端能力

> 读者：要把 GuiApi 接入自己的插件、并需要“按一个键打开界面 / 判断玩家装没装模组”的开发者。
> 前置阅读：[01-快速开始](01-快速开始.md)、[05-事件与交互](05-事件与交互.md)。
> 相关阅读：[06-图片与音效](06-图片与音效.md)、[08-布局技巧与常见问题](08-布局技巧与常见问题.md)。

GuiApi 的按键、客户端检测、命令执行都挂在同一个 `GuiApi` 实例上。这个实例是**全服共享**的，所以：

- 你的按键 id、窗口 id、资源 id 都要加插件前缀；
- 不要调用 `clearKeyHandlers()`、`clearKeys(player)`、`setClickSound(null, 0)` 这类“清空全局”的方法去清理自己，它们会连带影响别的插件；
- 只移除自己注册的 keyId。

## 7.1 判断客户端是否装了模组

### 7.1.1 方法

| 签名 | 作用 | 参数 | 注意 |
| --- | --- | --- | --- |
| `boolean isClientSupported(Player player)` | 玩家客户端是否完成 GuiApi 模组握手 | 玩家 | 没装模组、或刚上线握手还没到，都会返回 `false` |
| `String clientVersion(Player player)` | 客户端模组版本字符串，例如 `"1.3.12"` | 玩家 | 没装模组返回 `null`；装的是很旧的客户端、握手不带版本号时也返回 `null` |

推荐的门禁顺序：

```java
if (!api.isClientSupported(player)) {
    player.sendMessage("§c需要安装 GuiApi 客户端模组才能使用此功能");
    return;
}
if (!versionAtLeast(api.clientVersion(player), "1.3.12")) {
    player.sendMessage("§c客户端模组版本过低，请更新");
    return;
}
```

`isClientSupported` 为 `false` 时不代表玩家离线，只代表“这个客户端不能画 GUI”。此时不要发窗口，改为聊天提示或原版容器兜底。

握手是在玩家进入服务器之后才完成的，所以在 `PlayerJoinEvent` 里**立刻**判断有可能拿到 `false`。建议把判断放到第一次真正使用功能时（打开菜单、执行命令），或用调度器延后一拍：

```java
Bukkit.getScheduler().runTaskLater(this, () -> {
    if (api.isClientSupported(player)) {
        player.sendMessage("§aGuiApi 客户端已就绪");
    }
}, 20L);
```

### 7.1.2 版本比较

版本号是点分数字（`1.3.12`）。不要用字符串比较（`"1.3.9" > "1.3.12"` 会得到错误结果），按数字段比较：

```java
/** 客户端版本是否 >= 最低版本；version 为 null 视为不达标。 */
static boolean versionAtLeast(String version, String minimum) {
    if (version == null) return false;
    String[] a = version.split("\\.");
    String[] b = minimum.split("\\.");
    for (int i = 0; i < Math.max(a.length, b.length); i++) {
        int x = segment(a, i);
        int y = segment(b, i);
        if (x != y) return x > y;
    }
    return true;
}

private static int segment(String[] parts, int index) {
    if (index >= parts.length) return 0;
    String digits = parts[index].replaceAll("[^0-9].*$", ""); // 忽略 -SNAPSHOT 等后缀
    if (digits.isEmpty()) return 0;
    try {
        return Integer.parseInt(digits);
    } catch (NumberFormatException e) {
        return 0;
    }
}
```

版本策略参考：

| 你的功能 | 建议最低版本 |
| --- | --- |
| 窗口、图片、普通音效、按键 | `1.3.12` |
| `setLoopingSoundVolume` 实时改循环音量 | `1.3.13` |
| 只使用最基础的窗口 | 可放宽，但仍建议要求 `1.3.12` 以上 |

## 7.2 自定义按键

### 7.2.1 方法

| 签名 | 作用 | 参数 | 注意 |
| --- | --- | --- | --- |
| `void bindKey(Player player, String keyId, int keyCode)` | 给某个玩家绑定一个快捷键 | `keyId` 你自己命名；`keyCode` 为 **GLFW 键码** | `keyCode <= 0` 等价于解绑；对同一玩家重复绑定会覆盖旧键 |
| `void unbindKey(Player player, String keyId)` | 解绑一个快捷键 | 玩家、keyId | 只影响该玩家 |
| `void clearKeys(Player player)` | 清空该玩家**所有**服务端绑定的快捷键 | 玩家 | 会连别的插件绑的键一起清掉，慎用 |
| `void addKeyHandler(String keyId, Consumer<Player> handler)` | 注册按键回调 | keyId、处理函数 | 全服共享；同一 keyId 后注册的覆盖先注册的 |
| `void removeKeyHandler(String keyId)` | 移除按键回调 | keyId | 只移除自己的 keyId |
| `void clearKeyHandlers()` | 清空**所有**按键回调 | 无 | 会影响其他插件，只有你能控制整个服务器时才用 |

### 7.2.2 按键行为

- **GLFW 键码**，不是 Bukkit 的 `Material`、也不是字符。`A` 是 65，`R` 是 82，`K` 是 75。
- 服务端插件不依赖 LWJGL，**不要 `import org.lwjgl.glfw.GLFW`**（Paper 服务端没有这个类，编译会失败）。直接写整数字面量，或自己定义常量。
- 按下一次只触发一次（边沿触发），按住不会连发。
- **任意界面打开时都不触发**：聊天框、背包、箱子、暂停菜单、以及 GuiApi 自己的窗口。想“按键关闭窗口”是做不到的，请用窗口里的按钮或 Esc。
- 回调在服务端主线程执行，可以直接调用 Bukkit API。
- 绑定按玩家保存。玩家退出时服务端会清掉该玩家的绑定记录，重新登录后需要重新 `bindKey`；同一次在线期间客户端重新握手会自动重放已记录的绑定。
- 同一个键码只能对应一个 keyId：两个插件绑同一个键，后绑的会覆盖先绑的。反过来，一个 keyId 被重新绑定到新键码时，旧键码会失效。

### 7.2.3 常用键码

| 键 | 值 | 键 | 值 |
| --- | --- | --- | --- |
| A ~ Z | 65 ~ 90（A=65，Z=90） | 0 ~ 9 | 48 ~ 57 |
| 空格 | 32 | 回车 | 257 |
| Tab | 258 | Esc | 256 |
| 退格 | 259 | Delete | 261 |
| 左 Shift | 340 | 左 Ctrl | 341 |
| 左 Alt | 342 | 右 Shift | 344 |
| ↑ | 265 | ↓ | 264 |
| ← | 263 | → | 262 |
| F1 ~ F12 | 290 ~ 301 | Home / End | 268 / 269 |

选键建议：

- 避开 `W/A/S/D`、`E`、`Q`、`T`、`/`、`Esc`、`F5` 等原版正在使用的键。客户端只是轮询 GLFW 按键，**不会拦截**原版行为，按 `E` 会同时打开背包；
- 优先用 `K`、`J`、`R`、`G`、`H`、`N` 这类默认空闲的键；
- 一个插件只占一个键，不要把所有功能都塞到按键上。

### 7.2.4 完整示例

```java
import com.guiapi.paper.GuiApi;
import com.guiapi.paper.GuiWindow;
import org.bukkit.Bukkit;
import org.bukkit.entity.Player;
import org.bukkit.event.EventHandler;
import org.bukkit.event.Listener;
import org.bukkit.event.player.PlayerJoinEvent;
import org.bukkit.plugin.java.JavaPlugin;

public final class KeyShortcutDemo extends JavaPlugin implements Listener {

    /** 加插件前缀，避免和其他插件撞 id。 */
    private static final String KEY_MENU = "demo:menu";
    /** GLFW_KEY_K = 75。服务端不要 import LWJGL。 */
    private static final int KEY_K = 75;

    private GuiApi api;

    @Override
    public void onEnable() {
        api = GuiApi.get();
        api.addKeyHandler(KEY_MENU, this::openMenu);
        getServer().getPluginManager().registerEvents(this, this);
    }

    @EventHandler
    public void onJoin(PlayerJoinEvent event) {
        // 玩家每次上线都重新绑一次；服务端在退出时已清空该玩家的记录
        api.bindKey(event.getPlayer(), KEY_MENU, KEY_K);
    }

    private void openMenu(Player player) {
        if (!api.isClientSupported(player)) {
            player.sendMessage("§c需要 GuiApi 客户端模组");
            return;
        }
        if (!player.hasPermission("demo.menu")) return;

        GuiWindow window = new GuiWindow("demo_menu")
                .title("演示菜单")
                .size(260, 160);

        window.addLabel("welcome", 16, 14, "按 K 打开了这个窗口").color("#FFD166");
        window.addButton("close", 16, 110, 228, 28, "关闭")
                .backgroundColor("#FF333B48")
                .hoverColor("#FF455066")
                .textColor("#FFFFFFFF")
                .radius(6)
                .onClick(e -> api.closeWindow(e.player(), "demo_menu"))
                .widthPercent(88)
                .xPercent(6);

        api.openWindow(player, window);
    }

    @Override
    public void onDisable() {
        // 只移除自己的 keyId，不要 clearKeyHandlers()
        api.removeKeyHandler(KEY_MENU);
        for (Player online : Bukkit.getOnlinePlayers()) {
            api.unbindKey(online, KEY_MENU);
        }
    }
}
```

要点：

- `addKeyHandler` 写在 `onEnable`，只写一次；处理函数里再按权限、游戏状态过滤。
- `bindKey` 写在 `PlayerJoinEvent`；`onDisable` 里只清理自己的 keyId。
- 按键回调里打开窗口前先做 `isClientSupported` 判断。
- 不要在回调里直接 `openWindow` 后马上 `runCommand`，两者都会改窗口状态，顺序会很乱。

## 7.3 让客户端执行命令

### 7.3.1 方法

| 签名 | 作用 | 参数 | 注意 |
| --- | --- | --- | --- |
| `void runCommand(Player player, String command)` | 关掉该玩家所有 GuiApi 窗口，再让客户端以玩家身份执行命令 | `command`，开头带不带 `/` 都行 | 走客户端命令通道，等同玩家自己输入；服务端按玩家权限执行 |

行为细节：

1. **先关闭该玩家的所有 GuiApi 窗口**（不只是你的窗口），然后再执行命令。如果命令会打开另一个 GUI，正好避免两个界面叠在一起。
2. 客户端把命令当成聊天里输入的命令发送，所以服务端插件、命令方块的权限、其他插件的命令都能正常工作。
3. 命令执行是网络往返，不是同步完成。执行完想回到自己的界面，需要延后重新打开：

```java
api.runCommand(player, "otherplugin menu");
Bukkit.getScheduler().runTaskLater(this, () -> openMyWindow(player), 2L);
```

4. 命令写错不会抛异常，玩家会看到服务端的“未知命令”提示。发之前最好自己确认命令存在。

### 7.3.2 适用场景

| 场景 | 用法 |
| --- | --- |
| 打开另一个插件 / 客户端模组的界面 | `api.runCommand(player, "someplugin gui")` |
| 让玩家执行原版命令（返回出生点、打开商店） | `api.runCommand(player, "spawn")` |
| 需要由玩家身份触发权限 / 冷却 | 同上；不要用 `player.performCommand` 再自己关窗口 |

不适用：

- 只是执行你自己的服务端逻辑——直接调用方法，不要绕命令；
- 需要在同一 tick 内完成的连续操作——命令是异步往返的；
- 需要保留当前窗口的操作——`runCommand` 会先关闭所有窗口。

## 7.4 窗口生命周期与查询

### 7.4.1 方法

| 签名 | 作用 | 参数 | 注意 |
| --- | --- | --- | --- |
| `void onWindowClosed(String windowId, Consumer<GuiWindow> hook)` | 注册“客户端主动关闭窗口”的钩子 | 窗口 id、回调 | **只有玩家按 Esc / 点标题栏 × 时触发**；服务端自己 `closeWindow` 不会触发 |
| `Map<String, GuiWindow> windowsOf(Player player)` | 取该玩家当前打开的窗口表 | 玩家 | 没有窗口时返回空表；不要修改返回的 Map |

`onWindowClosed` 是按**窗口 id**注册的全局钩子，一个 id 只能有一个钩子，通常在 `onEnable` 注册一次：

```java
api.onWindowClosed("demo_menu", window ->
        getLogger().info("玩家关闭了 " + window.id()));
```

你需要玩家对象才能做业务，建议在钩子里结合窗口 id 自己查状态，或者改用按钮 / Esc 回调（`GuiWindow.onEscape`，见 [05-事件与交互](05-事件与交互.md)）。

`windowsOf` 适合在刷新前判断窗口是否还开着。`updateWidget` 对已关闭的窗口会被客户端静默忽略，先判断可以省掉无意义的包：

```java
if (api.windowsOf(player).containsKey("demo_lobby")) {
    api.updateWidget(player, "demo_lobby", "count", java.util.Map.of("text", "3 人"));
}
```

注意 `closeWindow(player, null)` 会关闭该玩家的**所有** GuiApi 窗口（包括其他插件的）。关闭自己的弹窗时永远传具体 id：

```java
api.closeWindow(player, "demo_confirm"); // 正确
// api.closeWindow(player, null);         // 会把底层主界面也关掉
```

## 7.5 客户端能力与边界

### 7.5.1 能做什么

| 能力 | 说明 |
| --- | --- |
| 绘制窗口与控件 | 按钮、标签、图片、输入框、滑块、勾选、单选框、下拉、物品图标 |
| 显示服务端图片 | 用 id 引用，客户端动态生成贴图，不需要资源包 |
| 播放服务端音效 | OGG，走主音量通道 |
| 服务端控制快捷键 | 客户端只轮询服务端下发的 GLFW 键码，不硬编码按键 |
| 以玩家身份执行命令 | `runCommand` |
| 系统字体 | 窗口可设 `font("guiapi:sysfont")`；客户端从玩家自己的 Windows 系统字体生成，找不到时回退原版字体 |

系统字体由客户端配置控制（`config/guiapi-client.txt`）：

```text
font=simhei.ttf
font_size=10
```

修改后需要重启客户端。不是所有玩家机器上都有同一个字体，所以**不要把关键信息做成只有系统字体才能看清的极小字号**。

### 7.5.2 做不到什么

- 客户端不执行服务端下发的任意脚本、不读玩家文件、不联网下载资源；
- 不能修改原版 HUD、不能拦截聊天、不能代替资源包；
- 不能在任意界面打开时抢按键；
- 不能在一个按键上挂多个 keyId（同一键码只保留最后一个）；
- 不能保证旧客户端支持新协议字段：新方法要先判断 `clientVersion`。

## 7.6 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 玩家按键没反应 | 没装模组；没 `bindKey`；玩家重登后没重新绑；当前有界面打开 | 检查 `isClientSupported`；在 `PlayerJoinEvent` 重新绑；让玩家关掉聊天 / 背包 |
| 按键被别的插件抢走 | 同一个键码又被后绑的 keyId 覆盖 | 换一个空闲键，或与其他插件协调键位 |
| 服务端编译报 `org.lwjgl` 找不到 | 在 Paper 插件里 import 了 LWJGL | 用整数字面量（K=75、R=82） |
| `clientVersion` 返回 `null` 但玩家能开界面 | 旧客户端握手不带版本号 | 按“不达标”处理，提示更新 |
| 玩家刚进服判断为不支持 | 握手还没到 | 延后判断，或在使用功能时判断 |
| 调用 `clearKeyHandlers()` 后别的插件按键失效 | 这是全服共享表 | 只 `removeKeyHandler(自己的 keyId)` |
| `runCommand` 后底层界面也没了 | 它会关闭该玩家全部 GuiApi 窗口 | 命令执行完再按需重开自己的窗口 |
| 弹窗关闭后底层也没了 | 用了 `closeWindow(player, null)` | 关闭弹窗时传具体 id |
| `onWindowClosed` 不触发 | 是服务端自己 `closeWindow` 关的 | 该钩子只监听客户端主动关闭；服务端关闭时自己处理后续逻辑 |

## 7.7 接入清单

- [ ] `plugin.yml` 里声明 `depend` 或 `softdepend: [GuiApi]`。
- [ ] `onEnable` 里 `GuiApi.get()`，并注册按键回调、关闭钩子。
- [ ] `PlayerJoinEvent` 里重新 `bindKey`。
- [ ] 所有 id 带插件前缀。
- [ ] 打开界面前判断 `isClientSupported`，需要新特性时再判断 `clientVersion`。
- [ ] `onDisable` 只移除自己的 handler / keyId，不清空全局。
- [ ] 需要跨插件跳转时用 `runCommand`，并注意它会先关掉所有窗口。
