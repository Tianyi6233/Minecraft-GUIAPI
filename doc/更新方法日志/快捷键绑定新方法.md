# GuiApi 按键设置 API

适用版本：GuiApi 客户端 **1.6.0+**（纯客户端能力，服务端无需改动）。

## 1. 两种快捷键

| 方式 | 谁注册 | 玩家能否改键 | 典型用途 |
| --- | --- | --- | --- |
| `GuiApi.bindKey(...)` | 服务端插件 | 否 | 插件自己的快捷入口，服务端随时下发/回收 |
| `GuiApiKeybinds.register(...)` | 客户端模组 | 是 | 需要出现在「选项 → 控制 → 按键绑定」里的快捷键 |

两者可以同时使用，互不影响。本文只介绍第二种。

## 2. 引入

```gradle
dependencies {
    // 编译时依赖 GuiApi 客户端
    modCompileOnly files("libs/guiapi-client-1.6.0.jar")
}
```

运行时由玩家安装 GuiApi 客户端与 Fabric API。

## 3. 方法签名

```java
public static KeyMapping register(String id, String label, Integer defaultKey)
public static KeyMapping register(String id, String label, Integer defaultKey, Runnable action)
public static KeyMapping get(String id)
```

| 参数 | 说明 |
| --- | --- |
| `id` | 唯一标识。重复注册同一 id 会直接返回已有绑定，不会创建第二个按键 |
| `label` | 显示在按键设置里的名称，直接作为文本使用 |
| `defaultKey` | GLFW 键码；传 `null` 表示默认不绑定，玩家可自行指定 |
| `action` | 可选。按键按下时自动执行，只在没有打开任何界面时触发 |

返回值为原版 `KeyMapping`，可以继续交给原版逻辑或自行轮询。

## 4. 调用时机

必须在客户端模组初始化阶段注册，早于原版按键列表构建：

```java
public class ExampleClient implements ClientModInitializer {
    @Override
    public void onInitializeClient() {
        registerKeys();
    }
}
```

在游戏运行中、进入世界后再调用，按键可以注册成功，但本次启动不会出现在按键设置界面里。

## 5. 示例一：自动执行动作

```java
import com.guiapi.client.api.GuiApiKeybinds;
import net.minecraft.client.Minecraft;
import org.lwjgl.glfw.GLFW;

public final class ExampleKeys {

    public static void register() {
        GuiApiKeybinds.register("example.open", "打开示例界面", GLFW.GLFW_KEY_K,
                () -> Minecraft.getInstance().setScreen(new ExampleScreen()));
    }
}
```

玩家可在按键设置里把 `K` 改成任意键；若与其它模组冲突，原版会显示冲突提示并允许改键。设置自动写入 `options.txt`，跨启动保留。

## 6. 示例二：默认不绑定 + 自行轮询

```java
import com.guiapi.client.api.GuiApiKeybinds;
import net.fabricmc.fabric.api.client.event.lifecycle.v1.ClientTickEvents;
import net.minecraft.client.KeyMapping;

public final class ExamplePolling {

    private static KeyMapping openKey;

    public static void register() {
        // null = 默认不绑定，由玩家在按键设置里指定
        openKey = GuiApiKeybinds.register("example.poll", "轮询示例", null);

        ClientTickEvents.END_CLIENT_TICK.register(client -> {
            if (client.screen != null || openKey == null) return;
            while (openKey.consumeClick()) {
                // 处理按键
            }
        });
    }
}
```

## 7. 注意事项

- **不会自动清空**：与服务器下发的隐形快捷键不同，这里的按键属于玩家设置，退出服务器、切换服务器都会保留。
- **只在游戏内触发**：原版按键绑定在打开任意界面时不会触发；`action` 形式也做了同样的限制。
- **分类名称**：所有按键显示在 `GuiApi` 分类下，翻译键为 `key.category.guiapi.main`，资源包可以覆盖。
- **冲突处理**：同一按键被多个功能占用时，由原版按键设置界面提示，玩家自行改键。
- **不要重复注册**：同一 id 重复调用是安全的，会返回第一次创建的绑定；但没有必要时不要创建大量按键，原版按键列表只适合有限数量。
