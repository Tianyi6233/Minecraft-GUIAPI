# 01 - 快速开始

本章目标：从空目录开始，做出一个能弹出、能点击、能刷新文字的窗口，并在服务器上跑通。完成后你就拥有了一个可继续扩展的 GuiApi 插件骨架。

---

## 1. 你会得到什么

做完本章后：

- 玩家在聊天框输入 `/gui`，客户端弹出一个小窗口（标题、一行文字、两个按钮）。
- 点「点我」，服务端聊天栏收到消息，窗口里的文字实时变成「按钮已点击」。
- 点「关闭」，窗口消失。
- 没装 GuiApi 客户端模组的玩家会收到一条提示，而不是看到一个空窗口。

## 2. 前置条件

| 位置 | 需要什么 | 检查方式 |
| --- | --- | --- |
| 服务端 | Paper **1.20.1 ~ 最新版** + Java 17+ | 控制台启动日志 |

## 3. 建工程

### 3.1 依赖

`pom.xml` 完整示例：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>my-gui-plugin</artifactId>
    <version>1.0.0</version>
    <packaging>jar</packaging>

    <properties>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <maven.compiler.release>17</maven.compiler.release>
    </properties>

    <repositories>
        <repository>
            <id>papermc</id>
            <url>https://repo.papermc.io/repository/maven-public/</url>
        </repository>
    </repositories>

    <dependencies>
        <dependency>
            <groupId>io.papermc.paper</groupId>
            <artifactId>paper-api</artifactId>
            <version>1.20.1-R0.1-SNAPSHOT</version>
            <scope>provided</scope>
        </dependency>
        <dependency>
            <groupId>com.guiapi</groupId>
            <artifactId>gui-api-paper</artifactId>
            <version>1.6.5</version>
            <scope>provided</scope>
        </dependency>
    </dependencies>
</project>
```

三个要点：

| 要点 | 原因 |
| --- | --- |
| `gui-api-paper` 的 `scope` 必须是 `provided` | GuiApi 的类由服务端的 GuiApi 插件提供。打进自己的 jar 会造成类重复，运行时报 `LinkageError` 或加载到错误版本 |
| `paper-api` 也用 `provided` | 服务端已经带了 Paper API，不需要也不应该打进 jar |
| 编码必须是 UTF-8 | 界面文案多为中文，源码乱码会直接显示成问号 |

如果 `gui-api-paper` 不在你的公共仓库里，先把 jar 装进本地 Maven 仓库：

```bash
mvn install:install-file -Dfile=gui-api-paper-1.6.4.jar -DgroupId=com.guiapi -DartifactId=gui-api-paper -Dversion=1.6.4 -Dpackaging=jar
```

或在 IDE 里把 `gui-api-paper-1.6.4.jar` 添加为项目的编译期库（不要勾选随产物打包）。

### 3.2 目录结构

```text
my-gui-plugin/
├─ pom.xml
└─ src/main/
   ├─ java/com/example/mygui/MyGuiPlugin.java
   └─ resources/plugin.yml
```

### 3.3 plugin.yml

```yaml
name: MyGuiPlugin
version: 1.0.0
main: com.example.mygui.MyGuiPlugin
api-version: '1.20'
depend: [GuiApi]
commands:
  gui:
    description: 打开 GuiApi 示例窗口
    usage: /gui
```

- **`depend: [GuiApi]` 必须写。** 它让服务端先启用 GuiApi 再启用你的插件，`GuiApi.get()` 才不会抛 `IllegalStateException`。
- `api-version` 填你要兼容的最低服务端版本；写 `'1.20'` 就能让同一个 jar 跑在 Paper 1.20.1 到最新版上。
- 你的插件名与 jar 文件名不必一致，`name` 是插件显示名。

## 4. 主类

```java
package com.example.mygui;

import com.guiapi.paper.GuiApi;
import com.guiapi.paper.GuiWindow;
import org.bukkit.command.Command;
import org.bukkit.command.CommandSender;
import org.bukkit.entity.Player;
import org.bukkit.plugin.java.JavaPlugin;

import java.util.Map;

public final class MyGuiPlugin extends JavaPlugin {
    /** 入口单例，在 onEnable 里取一次即可。 */
    private GuiApi api;

    @Override
    public void onEnable() {
        // GuiApi 插件已由 depend 保证先启用，这里不会抛 IllegalStateException
        api = GuiApi.get();
        getLogger().info("MyGuiPlugin 已接入 GuiApi");
    }

    @Override
    public boolean onCommand(CommandSender sender, Command command, String label, String[] args) {
        if (!(sender instanceof Player player)) {
            sender.sendMessage("只有玩家可以使用这个命令");
            return true;
        }
        // 没装客户端模组就开窗，玩家什么也看不到，先给一句提示
        if (!api.isClientSupported(player)) {
            player.sendMessage("§c请先安装 GuiApi 客户端模组");
            return true;
        }
        openHome(player);
        return true;
    }

    private void openHome(Player player) {
        GuiWindow win = new GuiWindow("demo_home")
                .title("我的第一个窗口")
                .size(260, 160);

        win.addLabel("hello", 16, 12, "你好，GuiApi！")
                .color("#FFD166")
                .scale(1.2f);

        win.addButton("click", 16, 34, 228, 22, "点我")
                .onClick(event -> {
                    event.player().sendMessage("§a按钮被点击了");
                    api.updateWidget(event.player(), "demo_home", "hello",
                            Map.of("text", "你已经点击过按钮"));
                });

        win.addButton("close", 16, 108, 228, 22, "关闭")
                .onClick(event -> api.closeWindow(event.player(), "demo_home"));

        api.openWindow(player, win);
    }
}
```

### 4.1 逐段说明

| 代码 | 说明 |
| --- | --- |
| `api = GuiApi.get()` | 取 API 单例。放在 `onEnable`，不要放静态字段初始化（那时 GuiApi 可能还没启用） |
| `new GuiWindow("demo_home")` | 创建一个窗口对象（只存在于服务端内存，尚未显示）。id 用于后续 `updateWidget` / `closeWindow` |
| `.title(...)` / `.size(260, 160)` | 链式设置属性，全部返回 `GuiWindow` 本身 |
| `win.addLabel(...)` | 添加文本控件，坐标 `(16, 12)` 相对**内容区**左上角（标题栏下方） |
| `win.addButton(...)` | 添加按钮：`(id, x, y, width, height, 文本)` |
| `.onClick(event -> ...)` | 绑定点击回调，事件在主线程触发，可直接操作 Bukkit |
| `event.player()` | 触发事件的玩家，回调里优先用它，不要依赖外层变量 |
| `api.openWindow(player, win)` | 真正把界面发给客户端。**只有调用它之后玩家才能看到窗口** |

### 4.2 关于链式调用

控件的大部分通用方法（`position`、`size`、`visible`、`xPercent`、`yPercent`、`widthPercent`、`heightPercent`、`aspect`、`tooltip`、`glow`、`hoverLift`、`anim` 等）返回的是基类 `Widget`，而控件专属方法（如 `Button.onClick`、`Label.color`、`Panel.radius`）返回具体控件类型。

因此链式调用时：

- 控件专属方法要写在前面，`Widget` 通用方法写在后面：`addButton(...).onClick(...).widthPercent(50)` 可以。
- 反过来 `addButton(...).widthPercent(50).onClick(...)` **不行**，因为 `widthPercent` 的返回值类型是 `Widget`，没有 `onClick`。
- 记不清顺序时就拆成变量，最稳妥：

```java
com.guiapi.paper.widget.Button close =
        win.addButton("close2", 0, 0, 0, 22, "关闭");
close.widthPercent(40);
close.xPercent(30);
close.yPercent(82);
close.onClick(event -> api.closeWindow(event.player(), "demo_home"));
```

### 4.3 尺寸与内容区

- 窗口默认 `260×160`，标题栏默认高 `16`，所以**内容区只有 144px 高**，控件 `y` 的可用范围是 `0 ~ 144`。
- 控件写在内容区外（`y + height > 144`，或超出窗口宽度）会被裁剪：看不见，也点不到。
- 上面的例子：第二个按钮 `y=108`，高 `22`，底边 `130 < 144`，安全。

## 5. 第一个交互

### 5.1 点击按钮

```java
win.addButton("ok", 16, 36, 228, 22, "确定")
        .onClick(event -> {
            Player p = event.player();          // 谁点的
            String winId = event.window().id(); // 哪个窗口（string）
            String widgetId = event.widget().id();
            p.sendMessage("§a你在 " + winId + " 点了 " + widgetId);
        });
```

`onClick` 的参数类型是 `Consumer<GuiActionEvent>`，写成 lambda 即可，不需要额外注册监听器。

### 5.2 关闭窗口

```java
api.closeWindow(player, "demo_home");   // 关闭一个
api.closeWindow(player, null);          // 关闭该玩家的全部窗口
```

注意 `closeWindow` 的 id 必须与 `new GuiWindow("demo_home")` 时一致。**建议在回调里用 `event.player()`，而不是命令执行时捕获的 `player`**，否则玩家换号/重连后可能操作到错误对象。

### 5.3 用标题栏关闭

默认窗口带标题栏和右上角关闭按钮，玩家点它或按 Esc 就能关。玩家主动关闭后，服务端可以通过 `onWindowClosed` 知道：

```java
api.onWindowClosed("demo_home", window ->
        getLogger().info("有玩家关闭了 demo_home"));
```

该回调按 windowId 全局注册，拿不到具体玩家；需要在关闭时清理“每个玩家”的状态时，请在自己的窗口操作里记录，或改用 `esc` 事件（见 02 章）。

## 6. 局部刷新：updateWidget

只改文字、颜色、显隐、数值时，不要重新 `openWindow`。重新开窗会让整个界面重建（输入框焦点丢失、下拉列表收起、玩家拖动的位置也可能被覆盖），而 `updateWidget` 只发一个小包：

```java
api.updateWidget(player, "demo_home", "hello",
        Map.of("text", "你已经点击过按钮", "color", 0xFF55FF55));
```

参数顺序：`(玩家, 窗口 id, 控件 id, 属性 Map)`。

### 6.1 常用属性 key

| key | 值类型 | 适用控件 | 说明 |
| --- | --- | --- | --- |
| `text` | String | Label、Button、TextField | 文本内容；Label 支持 `\n` 换行与 `§` 颜色代码 |
| `color` | int 或 String | Label | 文本颜色，ARGB |
| `visible` | boolean | 全部 | `false` 不绘制、不可点 |
| `value` | double | Slider | 滑块数值 |
| `checked` | boolean | Checkbox、Radio | 勾选状态 |
| `selected` | int | Dropdown | 选中项下标（从 0 开始） |
| `options` | List | Dropdown | 选项列表（字符串） |
| `image` | String | ImageWidget | 换图片 id（图片需已注册并已下发） |
| `bgColor` | int | Panel、Button、TextField | 背景色 |
| `hoverColor` | int | Panel、Button | 悬停背景色 |

Map 的 value 直接写 Java 值即可：数字发成 JSON 数字，布尔发成 JSON 布尔，字符串发成字符串，`List` 会逐项转成字符串。

### 6.2 四条硬规则

1. **先 `openWindow`，再 `updateWidget`。** 客户端只会更新已经显示的窗口；窗口没打开时这次更新被直接丢弃，不会缓存。
2. **不能增删控件。** 需要多一行、少一列时重新 `openWindow`。
3. **id 必须完全一致。** 窗口 id、控件 id 写错时客户端找不到目标，什么也不会发生（也不会报错）。
4. **服务端对象不会自动同步。** 玩家在客户端改了滑块/复选框/输入框，只有在你注册了对应的 `onChange` / `onToggle` / `onSelect` 时，GuiApi 才会把新值写回服务端的控件对象。若你随后重新 `openWindow`，会用服务端保存的值覆盖玩家刚才的输入。

## 7. 构建与部署

### 7.1 构建

```bash
mvn clean package
```

产物：`target/my-gui-plugin-1.0.0.jar`。

确认 jar 里**没有** `com/guiapi/paper/**`（说明 `provided` 生效）：

```bash
jar tf target/my-gui-plugin-1.0.0.jar
```

### 7.2 部署

| 位置 | 放什么 |
| --- | --- |
| 服务端 `plugins/` | `GuiApi-1.6.x.jar` 与 `my-gui-plugin-1.0.0.jar` |
| 客户端 `mods/` | `guiapi-client` 模组 jar 与 `fabric-api` |

重启服务端 → 启动客户端 → 进入服务器 → 输入 `/gui`。

### 7.3 验证顺序

1. 控制台有 `GuiApi ready on channel guiapi:main`，且没有你的插件报错。
2. `/plugins` 列表里同时有 GuiApi 与 MyGuiPlugin，且都显示绿色。
3. 执行 `/gui` 后聊天栏没有红色报错。
4. 客户端出现窗口，标题为「我的第一个窗口」。
5. 点「点我」后聊天栏收到消息，且窗口内文字变化。
6. 点「关闭」或标题栏 ×，窗口消失。

## 8. 排错表

| 症状 | 可能原因 | 处理 |
| --- | --- | --- |
| `/gui` 提示未知命令 | `plugin.yml` 没写 `commands`，或插件没被加载（看控制台报错） | 补 `commands`，执行 `/reload confirm` 或重启 |
| 控制台 `ClassNotFoundException: com.guiapi.paper.GuiApi` | 服务端没装 GuiApi 插件；或 GuiApi 没启用；或 `plugin.yml` 漏了 `depend` | 确认 `plugins/GuiApi-*.jar` 存在且 `depend: [GuiApi]` 已写 |
| 启动报 `NoClassDefFoundError` / `LinkageError` 且与 `com.guiapi` 相关 | 把 GuiApi 打进了自己的 jar（`scope` 不是 `provided`） | 改 `provided`，重新构建，确认 jar 内无 `com/guiapi` |
| 玩家执行命令后毫无反应，也没有报错 | 玩家没装客户端模组，`isClientSupported` 为 `false` | 装模组后重新进服；代码里先判断再提示 |
| 窗口一闪就没了 | 在 `onEnable` 里就给在线玩家开窗（当时还没握手/还没进游戏） | 改为命令或 `PlayerJoinEvent` 触发 |
| 能看到窗口但控件错位/跑到窗口外 | 内容区高度算错，忘了减去标题栏 16px；或把百分比当成了相对全屏 | 见 [02-窗口与坐标](./02-窗口与坐标.md) |
| 点按钮没反应 | 没绑 `onClick`；按钮被别的控件盖住；按钮在窗口外被裁剪 | 检查 id、坐标、是否设置了 `onClick` |
| `updateWidget` 没效果 | 窗口没打开；窗口 id/控件 id 拼错；想改结构却只发了属性 | 先确认窗口在客户端可见，id 逐字核对，结构变化重新 `openWindow` |
| 中文显示成 `?` | 源码编码不是 UTF-8 | `pom.xml` 加 `project.build.sourceEncoding=UTF-8`，IDE 文件编码设为 UTF-8 |
| 玩家重连后窗口消失 | 窗口是会话级的 | 在 `PlayerJoinEvent` 里按需重新 `openWindow` |
