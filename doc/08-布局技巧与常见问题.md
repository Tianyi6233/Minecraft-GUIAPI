## 8.1 虚拟画布与百分比

### 8.1.1 画布

客户端把界面画在一张设计尺寸为 **640 × 430** 的虚拟画布上，再整体缩放到实际屏幕：

- 屏幕小于 640×430 时，整张画布**等比缩小**，不会让固定像素的控件互相重叠；
- 屏幕大于 640×430 时，缩放保持 1:1，虚拟画布就等于实际像素（例如 1920×1080）；
- 缩放下限是 0.3，低于这个尺寸的极端小窗口会被裁切，不再继续缩小。

这带来两个直接结论：

1. **全屏窗口的宽高就是虚拟画布的宽高**，用 `widthPercent(100)` / `heightPercent(100)` 才能铺满；
2. **字号不随百分比放大**。大屏上百分比会把控件拉大，但文字仍是固定虚拟像素，看起来相对更小；重要文字要么用 `scale()` 放大，要么不要把依赖字号的排版硬拉到满屏。

### 8.1.2 百分比参照谁

| 属性 | 百分比相对 | 额外偏移 |
| --- | --- | --- |
| `xPercent(p)` | **窗口宽度** | 再叠加控件的 `x` 像素 |
| `yPercent(p)` | **内容区高度**（窗口高度 − 标题栏高度） | 再叠加控件的 `y` 像素 |
| `widthPercent(p)` | **窗口宽度** | 再叠加控件的 `w` 像素 |
| `heightPercent(p)` | **内容区高度** | 再叠加控件的 `h` 像素 |

所以：

- `yPercent` 不是相对窗口总高。默认窗口 260×160、标题栏 16px 时，内容区只有 144px；
- 使用百分比后，原来的 `w` / `h` 变成**附加偏移**，通常保持 0；负值可以用来内缩：

```java
// 宽度 = 窗口宽度的 100% 再减 20px，左右各留 10px 的观感
window.addPanel("bg", 10, 10, -20, 0)
        .widthPercent(100)
        .heightPercent(100);
```

- 尺寸 `w` / `h` 为负数时，客户端理解为“从右边 / 下边往里缩”：
  `w = -20` 表示宽度一直延伸到窗口右侧再减 20px；`h = -12` 同理。做右侧贴边栏、底部操作条时比算百分比稳。

### 8.1.3 负坐标 = 以中心为原点

控件的 `x < 0` 表示“以窗口横向中心为原点，再加 `x` **像素**偏移”，`y < 0` 表示“以内容区纵向中心为原点，再加 `y` 像素偏移”。注意它定位的是控件的**左上角**，不是控件中心：

```java
// 宽度为 0 的 Label 配 centered(true)：水平由客户端在整窗居中；y 仍是文字左上角，减半行高才视觉居中
window.addLabel("tip", -1, -5, "加载中…").centered(true);
```

- 宽度为 0 的标签（`Label` 默认宽度 0）配 `centered(true)` 时，水平方向由客户端在整窗居中，`x` 实际不参与；`y` 定位的仍是文字左上角，9px 高的文字想让中心落在内容区中心，用 `y = -5` 左右。
- 有宽度的控件（按钮、图片、面板）用负坐标只会把左上角放到中心附近，还需要自己减去一半尺寸；这时直接用 `xPercent(50 - 宽度百分比 / 2)` 更直观。
- 注意区分层级：`GuiWindow` 自身的 `x` / `y` 为负（默认 `-1`）表示**整个窗口居中**；本节讲的是**控件**的负坐标。

不要把它当成“百分比居中”：负坐标的偏移单位是像素。

### 8.1.4 宽度百分比 → 高度百分比

图片、卡牌需要保持原始宽高比时，最稳的做法是 `widthPercent(...).aspect(宽/高)`。只有当你确实按 640×430 设计稿搭窗口时，才用下面这个换算：

```
高度百分比 = 宽度百分比 ÷ 100 × 640 ÷ aspect ÷ 430 × 100
```

其中 `aspect = 素材宽 / 素材高`。

工具方法：

```java
/** 全屏 + titleBar(false) 的 640×430 画布。 */
static double heightPct(double widthPct, double aspect) {
    return heightPct(widthPct, aspect, 640, 430);
}

/** 通用版本：widthBase 为窗口宽度，contentH 为内容区高度。 */
static double heightPct(double widthPct, double aspect, double widthBase, double contentH) {
    return widthPct / 100.0 * widthBase / aspect / contentH * 100.0;
}
```

常用换算（全屏 640×430）：

| 场景 | 宽度百分比 | aspect（宽/高） | 算出的高度百分比 |
| --- | --- | --- | --- |
| 卡牌 160×225 | 12% | 0.7111 | ≈ 25.1% |
| 宽按钮 168×85 | 15% | 1.9765 | ≈ 11.3% |
| 正方形头像 | 8% | 1.0 | ≈ 11.9% |
| 竖图猫爪 347×762 | 18% | 0.4554 | ≈ 58.8% |
| 全屏背景 | 100% | 不适用 | 直接用 `heightPercent(100)` |

计算过程示例（卡牌 12%）：`12 / 100 × 640 = 76.8px` 宽，`76.8 / 0.7111 ≈ 108px` 高，`108 / 430 × 100 ≈ 25.1%`。

**重要**：这个简写只在「虚拟画布恰好 640×430 + 隐藏标题栏」时准确（小屏幕或高 GUI 缩放）。屏幕较大时画布会大于 640×430，必须用上面的三参数版本，或者直接用 `aspect()`。标题栏可见时内容区高度也要从 430 里扣掉。

## 8.2 等比与图片填充

### 8.2.1 aspect

`aspect(double widthOverHeight)` 用“宽度 / 高度”锁定比例，客户端会**根据最终宽度反算高度**：

```java
window.addImage("card", 0, 0, 0, 0, "demo_card")
        .fit("contain")
        .widthPercent(12)
        .aspect(160.0 / 225.0)
        .xPercent(44)
        .yPercent(40);
```

规则：

- `aspect` **优先于** `heightPercent` 和 `h`。同时写 `aspect(...)` 和 `heightPercent(...)` 时，高度按 aspect 算，`heightPercent` 被忽略——这是“为什么我设了高度没反应”的最常见原因。
- `aspect` 只锁比例，不负责缩放；最终大小仍由 `widthPercent(…)` 或 `w` 决定。
- 只有宽度可变、高度想跟着变的控件才用 aspect；背景图直接 `widthPercent(100).heightPercent(100)`。

### 8.2.2 fit

| fit | 行为 | 什么时候用 |
| --- | --- | --- |
| `stretch`（默认） | 拉伸到控件框，比例会变 | 纯色块、可拉伸的底图 |
| `cover` | 等比放大到填满，裁掉超出部分 | 全屏背景、封面，不能变形 |
| `contain` | 等比缩小到完整可见，四周留空 | 卡牌、图标、带透明边的按钮图 |

素材本身带透明边距时，`contain` 会把透明边距也当成图片内容，视觉上图案会偏小、偏心。导出素材前**裁掉透明边距**，再登记宽高比。

## 8.3 适配不同分辨率

### 8.3.1 推荐做法

1. 所有需要铺满的界面用 `fullscreen(true)` + `titleBar(false)` + 百分比；
2. 图片用 `aspect` 锁定比例，不要同时写死宽高；
3. 间距、边距用百分比；字号和按钮高度可以用固定像素（保证可读性）；
4. 窗口背景用 `fit("cover")`，避免拉伸变形；
5. 不要混用“固定像素坐标 + 百分比尺寸”，窗口一改大小就会错位。

全屏背景的标准写法：

```java
GuiWindow window = new GuiWindow("demo_page")
        .fullscreen(true)
        .titleBar(false)                 // 内容区才会等于整张画布
        .backgroundColor("#00000000")    // 窗口自身底色透明，交给背景图
        .borderWidth(0);

window.addImage("bg", 0, 0, 0, 0, "demo_bg")
        .fit("cover")
        .widthPercent(100)
        .heightPercent(100);
```

### 8.3.2 标题栏的影响

内容区从标题栏下方开始。`titleBar(true)` 时：

- `yPercent(0)` 是标题栏下沿，不是窗口顶端；
- `heightPercent(100)` 只铺满内容区，**顶部会留下标题栏**；
- 全屏封面图如果忘了 `titleBar(false)`，最上面会有一条 16px 的标题栏色带。

做全屏视觉页时统一 `titleBar(false)`；需要拖动和关闭按钮的小工具窗口才保留标题栏。

### 8.3.3 自测清单

至少检查这些组合：

| 场景 | 关注点 |
| --- | --- |
| 1280×720 | 16:9 基准 |
| 1920×1080 | 大屏下字号是否偏小、百分比按钮是否过大 |
| 1024×768 / 4:3 | 比例变化时元素是否重叠 |
| 超宽屏 | 全屏背景 `cover` 是否裁到关键内容 |
| 游戏窗口化、很小 | 整体缩放后文字是否还可读 |
| GUI 缩放 2 / 3 / 4 | 控件与文字的相对大小 |

不要只在开发机的 1920×1080 上看一次就交付。

## 8.4 层次、遮挡与遮罩

### 8.4.1 窗口层级

- 后打开的窗口画在上层；
- 点击某个窗口会把它提到最前；
- `alwaysOnTop(true)` 的窗口永远在最上层，点击下层窗口也不会被压下去；
- 重新 `openWindow` 同一个 id 会把该窗口提到最前（`alwaysOnTop` 的除外）。

这就是“弹窗一定要 `alwaysOnTop`”的原因：底层全屏界面如果因为状态刷新被重新 `openWindow`，会重新提到前面，没设 `alwaysOnTop` 的弹窗就会被盖住。

### 8.4.2 同一窗口内的控件顺序

同一窗口内同时存在两套顺序，容易踩坑：

| 维度 | 规则 |
| --- | --- |
| 绘制 | 按添加顺序，**后添加的画在上层** |
| 点击命中 | 按添加顺序，**先添加的可点击控件先拿到点击** |

因此：

- 透明点击层要**先添加**，它会在视觉上位于卡面下方，但点击时优先命中；
- 纯装饰、不接收点击的 Panel 不会消费点击（`clickable` 为空），点击会继续传给后面的可点击控件；
- 两个都可点击且重叠的控件，先添加的那个永远赢，即使它被后添加的图盖住。

典型手牌写法：

```java
// 1. 先加透明点击层：负责点击 / 拖动 / tooltip
var hit = window.addPanel("hit0", 0, 0, 0, 0);
hit.borderWidth(0).backgroundColor("#00000000")
        .onClick(e -> selectCard(e.player(), 0));
if (canDrag) hit.dragGroup("hand");
hit.widthPercent(12).aspect(160.0 / 225.0).xPercent(40).yPercent(70);

// 2. 再加卡面：视觉在上层，不接管点击；要跟随拖动就挂同一个 dragGroup
var img = window.addImage("card0", 0, 0, 0, 0, "demo_card");
img.fit("contain");
if (canDrag) img.dragGroup("hand");
img.widthPercent(12).aspect(160.0 / 225.0).xPercent(40).yPercent(70);
```

### 8.4.3 遮罩 / 模态弹窗

`dim(alpha)` 是窗口背后的整屏压暗层，取值 0~255：

```java
GuiWindow confirm = new GuiWindow("demo_confirm")
        .fullscreen(true)          // 必须全屏，才能挡住整屏点击
        .titleBar(false)
        .backgroundColor("#00000000")
        .borderWidth(0)
        .alwaysOnTop(true)         // 不被底层刷新盖住
        .dim(150)                  // 压暗程度
        .closeOnEsc(false)         // Esc 不直接关，交给服务端
        .onEscape(e -> api.closeWindow(e.player(), "demo_confirm"));

confirm.addPanel("card", 0, 0, 0, 0)
        .borderWidth(0).backgroundColor("#F018181C").radius(10)
        .widthPercent(30).heightPercent(30)
        .xPercent(35).yPercent(30);

confirm.addButton("cancel", 0, 0, 0, 26, "取消")
        .radius(8)
        .onClick(e -> api.closeWindow(e.player(), "demo_confirm"))
        .widthPercent(12).xPercent(37).yPercent(52);

api.openWindow(player, confirm);
```

要点：

- **`dim` 本身不挡点击**。真正挡住下层的是这个全屏窗口：窗口背景会消费窗口矩形内的所有点击。所以模态框必须 `fullscreen(true)`，小窗口只能挡住自己那块区域。
- **`dim` 不会叠加**。客户端取所有窗口 `dim` 的最大值，只铺一层；同时开两个弹窗不会更黑。
- `closeOnEsc(false)` 时，Esc 和标题栏 × 都会转成 `"esc"` 事件发给服务端；必须配 `onEscape(...)`，否则 Esc 完全关不掉窗口。
- 关闭弹窗只关弹窗 id，**不要 `closeWindow(player, null)`**，那会把底层主界面一起关掉。
- 底层窗口不用关，它会被全屏遮罩挡住；玩家点不到。
- 如果只是“操作中禁止点击”的遮罩，不想写按钮，可以开一个全屏透明窗口 + 一个半透明 Panel，`alwaysOnTop(true)`，不放任何可点击控件；完成时关闭它。

透明遮罩面板：

```java
GuiWindow mask = new GuiWindow("demo_mask")
        .fullscreen(true).titleBar(false)
        .backgroundColor("#00000000").borderWidth(0)
        .alwaysOnTop(true);
mask.addPanel("shade", 0, 0, 0, 0)
        .borderWidth(0).backgroundColor("#40000000")
        .widthPercent(100).heightPercent(100);
api.openWindow(player, mask);
```

### 8.4.4 悬停与 tooltip

- 只有鼠标下**最上层窗口**里的控件会响应悬停；
- 被窗口裁掉的控件（超出窗口矩形）不显示 tooltip；
- 展开的下拉选项、tooltip 是最后绘制的，会盖在所有窗口上；下拉选项即使画到窗口外，点击也由它所属的窗口处理，不会传给别的窗口。

## 8.5 能力边界

先把“做不到”的事情说清楚，避免用错方案：

| 需求 | GuiApi 的边界 | 替代方案 |
| --- | --- | --- |
| 旋转图片 / 旋转文字 | **没有旋转能力** | 预先生成多张旋转好的图片，按帧快速切换（见 [09-实战案例](09-实战案例.md) 的爆炸特效） |
| 补间旋转、缩放、透明度 | 只有位置补间 `anim(ms, ease)` 和悬停上浮 3px | 多帧图 + 位置抖动；颜色透明度写在 ARGB 里 |
| 纵向滚动列表 | 没有“滚动容器”，控件不会跟着滑动条自动滚动 | 用 `addScrollbar` 拿到 `0–100` 的数值，在 `onChange` 里换算偏移量并 `updateWidget` 换文字（见 [04-表单控件](04-表单控件.md) 的 Scrollbar）；手牌用 `dragGroup` 横向拖动 |
| 横向滚动条 | `Scrollbar` 只做纵向；`dragGroup` 只在整组宽度超出窗口时可拖，且没有滚动条 | 横向用 `dragGroup`，或自己画一个进度条提示 |
| 任意形状裁剪 | 只按窗口矩形裁剪；下拉选项是例外可以溢出 | 把超出的部分放到窗口外，或拆成多个窗口 |
| 自定义着色器、动画 GIF | 图片是静态贴图 | 多帧图切换 |
| 每个控件独立透明度动画 | 只能用 ARGB 静态透明色 | 多帧图 / 叠半透明 Panel |
| 富文本混排 | 文本是单个字符串 | 用多个 Label 拼 |
| 音效左右声道、3D 定位 | 统一走 MASTER，居中播放 | 无 |
| 界面打开时抢按键 | 任意界面（含聊天、背包、GuiApi 窗口）打开时按键都不触发 | 用按钮、Esc、窗口内交互 |

`dragGroup` 的两个细节：

- 只有整组控件的总宽度超过窗口时才能拖动；能放下时拖动无效；
- 拖动和点击由客户端区分：移动超过约 3px 算拖动，不触发点击；没移动就松开才算点击。所以手牌“拖一下再松手”不会误选牌。

### 金色描边不是“光晕”

`glow("#FFD700")` 实际画的是控件外接矩形的三层 1px 描边，不是柔和的模糊光晕。表现：

- 宽高不规则的图片会得到一个**方框**，不是贴合轮廓的光；
- 亮金色 + 多层嵌套控件时非常抢眼，容易显得脏；
- 描边向外扩 3px，贴窗口边缘时会被裁掉。

建议只给“当前选中 / 当前回合”的一个控件加，颜色带透明度（如 `#99FFD700`），不要整屏每个按钮都加。

## 8.6 常见坑

### 8.6.1 链式调用返回类型

基类 `Widget` 的通用方法（`position`、`size`、`visible`、`tooltip`、`xPercent`、`yPercent`、`widthPercent`、`heightPercent`、`aspect`、`dragGroup`、`glow`、`hoverLift`、`anim`）返回的是 `Widget`，不是具体控件类型。

```java
// 错误：widthPercent 返回 Widget，后面找不到 fit / onClick
window.addImage("card", 0, 0, 0, 0, "demo_card")
        .widthPercent(12)
        .fit("contain");           // 编译失败

// 正确：控件专属方法写在百分比之前
window.addImage("card", 0, 0, 0, 0, "demo_card")
        .fit("contain")
        .onClick(e -> api.playSound(e.player(), "demo_click"))
        .widthPercent(12)
        .aspect(160.0 / 225.0);
```

同理，`Button.onClick`、`Panel.radius` / `gradient`、`ImageWidget.fit`、`Label.centered` / `color` / `scale`、`Checkbox.onToggle`、`Slider.onChange`、`Dropdown.onSelect`、`TextField.onChange` 都要放在 `widthPercent` / `xPercent` / `aspect` 等通用方法**之前**。

如果必须分开写，用中间变量：

```java
var button = window.addButton("ok", 0, 0, 0, 26, "确定");
button.radius(8).onClick(e -> doOk(e.player()));
button.widthPercent(20).xPercent(40).yPercent(60);
```

### 8.6.2 id 重复会静默覆盖

`GuiWindow` 内部按 id 保存控件，**后添加的同 id 控件会覆盖先添加的**，不报错、不警告。表现为“某个按钮怎么点都没反应”或“图片不见了”。

- 循环生成控件时 id 一定要带下标：`"card" + i`；
- 不要用同一个 id 既做点击层又做卡面（点击层用 `hit0`，卡面用 `card0`）；
- 窗口 id 也要加插件前缀，避免多个插件互相覆盖窗口。

### 8.6.3 重绘会丢客户端本地状态

`openWindow` 同一个窗口 id 时，客户端用新模型替换旧内容：

- 窗口被拖动过的位置会保留；
- **输入框焦点、光标位置会丢**；鼠标悬停 / tooltip 会在下一帧按新控件重新计算，不保留旧状态；
- 勾选框 / 单选框 / 下拉 / 滑块的显示值以新模型里写入的值为准。

所以：

- 不要在玩家打字时整窗重绘，用 `updateWidget` 改文本；
- 重绘前把服务端保存的状态（选中项、勾选值、滑块值）重新写进控件；
- 重绘后想恢复焦点，需要客户端重新点一次输入框，API 没有“强制聚焦”能力。

### 8.6.4 图片 / 音效资源

| 现象 | 原因 |
| --- | --- |
| 图片空白 | 没注册；id 大小写不一致；JPEG 解码失败；`updateWidget` 换的新图没 `preloadImage` |
| 音效无声 | 文件不是 OGG；id 没注册；玩家主音量为 0；首次资源包还没装好 |
| 换图后仍是旧图 | 只改了控件引用，没有重发图片；需要重新注册 + `sendImage` |

详见 [06-图片与音效](06-图片与音效.md)。

### 8.6.5 hidden 控件仍占 id

`visible(false)` 只是不画、不响应点击，控件**仍留在窗口里**：

- 它的 id 仍被占用，再 `addXxx` 同 id 会覆盖它；
- 仍然可以用 `updateWidget(..., Map.of("visible", true))` 重新显示；
- 每次重绘仍会把它写进窗口 JSON，大量永久隐藏的控件是浪费。

需要按条件出现的控件，要么复用同一个 id 改 `visible` / `text` / `image`，要么在构建窗口时决定是否添加。

### 8.6.6 updateWidget 属性名写错 = 静默无效

客户端只是把 `props` 合并进控件模型，**属性名不匹配就不会有任何效果**，也没有报错。常用正确属性名：

| 控件 | 可更新属性（常用） |
| --- | --- |
| 所有控件 | `visible`、`tooltip`、`x`、`y`、`w`、`h`、`xPct`、`yPct`、`wPct`、`hPct` |
| `label` | `text`、`color`、`center`、`scale` |
| `button` | `text`、`bgColor`、`hoverColor`、`textColor` |
| `image` | `image`、`fit` |
| `panel` | `bgColor`、`hoverColor`、`borderColor`、`borderWidth`、`radius` |
| `slider` | `value`、`min`、`max`、`step`、`label` |
| `checkbox` | `checked`、`label` |
| `radio` | `checked`、`label` |
| `dropdown` | `options`、`selected` |
| `text_field` | `text`、`placeholder` |

最容易写错的几个：

| 写成 | 正确 |
| --- | --- |
| `imageId` | `image` |
| `centered` | `center` |
| `backgroundColor` | `bgColor` |
| `shown` / `show` | `visible` |
| `checked` 用在 label 上 | label 没有 checked |

颜色注意：`updateWidget` 里传 `"color"` / `"bgColor"` 时要用 **int ARGB**（例如 `0xFF6B6B`），不要传 `"#FF6B6B"` 字符串。字符串会被原样写进模型，客户端按数字读取时取不到值，颜色不会变。

```java
// 正确
api.updateWidget(player, "demo_hud", "status",
        java.util.Map.of("text", "已连接", "color", 0xFF5BE39A));

// 错误：颜色是字符串
api.updateWidget(player, "demo_hud", "status",
        java.util.Map.of("text", "已连接", "color", "#5BE39A"));
```

另外：`updateWidget` 只在窗口当前打开、且控件 id 存在时生效。窗口已关闭时客户端静默忽略；刷新前可以用 `api.windowsOf(player).containsKey(windowId)` 判断。

### 8.6.7 百分比与坐标的常见错误

| 错误 | 说明 | 修正 |
| --- | --- | --- |
| 把 `yPercent` 当窗口高度的百分比 | 它相对的是内容区高度（高度 − 标题栏） | 记住内容区，或用 8.1.4 的三参数 `heightPct` 工具方法换算 |
| 同时写 `aspect` 和 `heightPercent` | `aspect` 优先，高度百分比被忽略 | 二选一 |
| 全屏背景 `heightPercent(100)` 仍有顶部空隙 | 标题栏占了 16px | `titleBar(false)` |
| 百分比尺寸 + 固定坐标混排 | 窗口尺寸一变就错位 | 统一用百分比 |
| 用 640×430 公式算普通窗口 | 参照尺寸不同 | 普通窗口传自己的宽度 / 内容高 |
| 以为 `xPercent(50)` 是居中 | 它是“窗口宽度 50% 处”作为左边缘 | 居中用 `xPercent(50 - 宽度百分比/2)`，或负坐标中心 |

### 8.6.8 窗口与音效生命周期

- `closeWindow` 不会停止音效，BGM 会继续响；
- `closeWindow(player, null)` 会关闭该玩家所有 GuiApi 窗口，包括别的插件和自己的主界面；
- `runCommand` 也会先关闭所有窗口；
- 服务端自己关闭窗口不会触发 `onWindowClosed`，该钩子只监听客户端主动关闭；
- 玩家退出时要主动 `stopSound` / `stopAllSounds`，否则客户端可能残留循环音。

### 8.6.9 按键

按键在任意界面打开时不触发（聊天、背包、GuiApi 窗口）。所以不要设计“按 K 关闭当前 GUI”，用按钮或 Esc。详见 [07-按键与客户端能力](07-按键与客户端能力.md)。

### 8.6.10 手牌 / 长列表

- `dragGroup` 只横向、只在超出窗口时可拖；能放下时拖动无效；
- 拖动组内的控件位置变化**不做位置补间**，否则会拖泥带水；
- 整组拖动范围被限制在“不能拖出右边界、不能向右拖过初始位置”；
- 想显示“还能往左拖”的提示，需要自己根据选中 / 排序状态加箭头或渐变。

## 8.7 性能建议

| 建议 | 原因 |
| --- | --- |
| 先 `openWindow`，后续小改动用 `updateWidget` | 重绘会重发整窗 JSON，且丢输入焦点 |
| 不要每 tick 重绘 | 客户端每帧都要重新布局 / 绘制；按 5 tick（250ms）或状态变化刷新即可 |
| 大量字段一起变时，宁可整窗重绘一次 | `updateWidget` 一次只能改一个控件，几十个控件就是几十个包 |
| 资源在 `onEnable` 注册、登录时 `preload` | 避免第一次出现时传输 / 装包造成卡顿 |
| 图片按实际显示尺寸准备，别上 4K 大图 | 传输、解码、显存都按原图算 |
| 动画优先改位置，少用逐帧换图 | 换图需要准备多张素材，且每帧都要重绘 |
| 控件数量控制在几十个以内 | 每个控件每帧都要布局、绘制、命中检测；几百个会明显拖慢 |
| 不要给所有控件加 `glow` / `hoverLift` | 视觉噪音大，描边还会超出边界被裁 |
| 玩家退出 / 离开牌局时关窗口、停音效、清自己的 handler | 避免残留循环音和旧插件实例的回调 |
| 刷新前先判断窗口是否打开 | 省掉对已关闭窗口的无效包 |
