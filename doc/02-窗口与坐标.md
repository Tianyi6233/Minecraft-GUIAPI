# 02 - 窗口与坐标

本章讲两件事：`GuiWindow` 的每个属性到底控制什么，以及「控件到底会画在哪里」。布局问题绝大多数都出在坐标体系没理清，建议按顺序读完。

本章的代码片段默认你已经持有 `GuiApi api` 和 `GuiWindow win` 两个变量，并已 import `com.guiapi.paper.GuiApi`、`com.guiapi.paper.GuiWindow` 与 `com.guiapi.paper.widget.Button`（完整工程见 [01-快速开始](./01-快速开始.md)）。

---

## 0. 三层坐标，一句话记住

```text
虚拟画布（整个屏幕，640×430 为设计基准）
└─ 窗口（左上角 x/y，宽 w、高 h，可被玩家拖动）
   └─ 标题栏（默认高 16px）
   └─ 内容区（窗口高 - 标题栏高）
      └─ 控件（坐标原点 = 内容区左上角；xPercent 相对窗口宽，yPercent 相对内容区高）
```

- 所有数值都是**虚拟像素**，不是真实屏幕像素。
- 控件的 `(0, 0)` 在**标题栏下方**，不是窗口最左上角。
- 窗口尺寸本身没有百分比写法；要响应式就用 `fullscreen(true)` + 控件百分比。

另一个使用层面的重要事实：只要该玩家有任意一个 GuiApi 窗口打开，客户端就处于一个 GUI 屏幕中，鼠标用来操作界面、不能转视角；但游戏不会被暂停，玩家仍会掉血、仍会被怪打。

---

## 1. 虚拟画布

客户端会把当前屏幕换算成一个「虚拟画布」，再在画布上按虚拟像素绘制所有窗口：

- 设计基准是 `640×430`。
- 换算比例 `uiScale = min(1, 屏宽/640, 屏高/430)`，最低不会小于 `0.3`；虚拟画布尺寸 = 屏幕逻辑尺寸 / `uiScale`。
- 屏幕足够大时 `uiScale = 1`，虚拟画布就等于屏幕的逻辑尺寸（例如 1920×1080、GUI 缩放 2 时约为 `960×540`），此时一个 `260` 宽的窗口只占屏幕约 27%。
- 屏幕太小或 GUI 缩放太大时整体等比缩小，保证 640×430 的界面不会互相重叠，但文字也会一起变小。

由此得到两条实践结论：

| 场景 | 建议 |
| --- | --- |
| 固定大小的小面板/提示框 | 用固定像素（`size(260, 160)`），在大画布上会显得小一些，属正常现象 |
| 全屏界面、卡片列表、背景图 | 用 `fullscreen(true)` + 百分比布局，否则换分辨率就会错位 |
| 想做“设计稿 640×430”的精确还原 | 按 640×430 设计，并用第 8 节的换算公式 |

## 2. 窗口位置

```java
GuiWindow win = new GuiWindow("demo_fixed")
        .title("固定位置")
        .size(300, 200)
        .position(40, 30);      // 左上角放在虚拟画布的 (40, 30)
```

| 方法 | 作用 | 默认 | 注意 |
| --- | --- | --- | --- |
| `new GuiWindow(String id)` | 创建窗口 | — | id 必填；同一玩家同 id 只会有一个窗口 |
| `id()` | 读窗口 id | — | `updateWidget` / `closeWindow` 都用它 |
| `position(int x, int y)` | 窗口左上角位置 | `-1, -1` | **任何负数都表示居中**（不只是 -1）；`>= 0` 才是绝对坐标 |
| `posX()` / `posY()` | 读回设置的位置 | — | 返回你设置的值；玩家拖动后的实际位置拿不到 |
| `size(int width, int height)` | 窗口尺寸 | `260 × 160` | `fullscreen(true)` 时被忽略 |
| `width()` / `height()` | 读回尺寸 | — | 返回设置值；`fullscreen(true)` 时不代表实际绘制尺寸 |
| `fullscreen(boolean)` | 全屏 | `false` | 宽高直接取虚拟画布，忽略 `position` / `size` |
| `draggable(boolean)` | 是否可拖标题栏 | `true` | 只认标题栏拖动；`titleBar(false)` 或 `titleHeight(0)` 时拖不动；全屏不可拖 |
| `draggable()` / `fullscreen()` | 读回开关 | — | — |

### 2.1 居中

```java
GuiWindow centered = new GuiWindow("demo_center")
        .size(280, 180)
        .position(-1, -1);      // 水平、垂直都居中
```

居中是相对**虚拟画布**算的：`(画布宽 - 窗口宽) / 2`，垂直同理。全屏窗口铺满画布，居中与否没有区别。

### 2.2 位置的保留规则（容易误解）

| 操作 | 窗口位置 |
| --- | --- |
| 第一次 `openWindow` | 按 `position()` 计算；负数则居中 |
| 玩家拖动标题栏 | 位置改变，**本次会话内记住** |
| 同 id 再次 `openWindow` | 内容整体替换，**保留玩家拖动后的位置**（你新写的 `position()` 不生效） |
| `closeWindow` 后再 `openWindow` | 重新按 `position()` / 居中计算 |
| 玩家重连 | 全部窗口消失，重新打开时重新计算 |

所以“我改了 `position()` 但界面没动”通常不是 bug，而是该窗口还开着且被拖动过。调试时先 `closeWindow` 再打开。

### 2.3 边界

客户端不限制窗口位置：玩家可以把窗口拖到屏幕外，只留一条边。需要固定就 `draggable(false)`。窗口被拖出画布后，超出画布的部分不会被绘制，但仍可拖回来（只要还能点到标题栏）。

## 3. 尺寸、标题栏与内容区

### 3.1 关系

```text
窗口高度 h
├─ 标题栏高度 titleHeight（默认 16，titleBar=false 时为 0）
└─ 内容区高度 = h - titleHeight
```

- 控件的 `y` 从内容区顶部开始量。`y = 0` 是标题栏下方的第一条像素。
- `size(260, 160)` 时内容区只有 `160 - 16 = 144` 高。
- 内容区宽度 = 窗口宽度（边框不占布局宽度；1px 边框画在窗口边缘内侧，贴边的控件会盖住它，想让边框露出来就留 1px 内边距）。

### 3.2 标题栏属性

| 方法 | 作用 | 默认 | 注意 |
| --- | --- | --- | --- |
| `title(String)` | 标题文字 | `""` | 空字符串时标题栏仍然存在，只是没字 |
| `titleBar(boolean)` | 是否显示标题栏 | `true` | `false` 时内容区多出 16px，同时**没有内置关闭按钮**，需要自己加按钮 |
| `titleHeight(int)` | 标题栏高度 | `16` | `<= 0` 等价于没有标题栏；`< 14` 时右上角 × 画得出但点不到；`<= 0` 也无法拖动 |
| `titleBarColor(String/int)` | 标题栏底色 | `0xFF2D2F38` | `style("minecraft")` 时被固定配色覆盖 |
| `titleColor(String/int)` | 标题文字颜色 | `0xFFFFFFFF` | 两种 style 下都生效 |

标题栏内部固定布局（不需要也不能改）：

- 标题文字左边距 `6px`，在标题栏内垂直居中。
- 右上角关闭按钮 `12×12`，距窗口右边缘 `14px`；标题太长会被按钮盖住，建议自己截断。
- 只有标题栏高度 `>= 14` 时关闭按钮才可点。

### 3.3 无标题栏窗口

```java
GuiWindow borderless = new GuiWindow("demo_borderless")
        .titleBar(false)
        .size(300, 180);

borderless.addLabel("hint", 16, 12, "没有标题栏，需要自己放关闭按钮");
borderless.addButton("close", 0, 0, 0, 24, "关闭")
        .onClick(event -> api.closeWindow(event.player(), "demo_borderless"))
        .widthPercent(30)
        .xPercent(35)
        .yPercent(76);
```

无标题栏窗口仍然可以用 Esc 关闭（`closeOnEsc` 默认 `true`），但没有 × 可点；`draggable` 对它是无效的。

## 4. 外观属性

| 方法 | 作用 | 默认值 | 注意 |
| --- | --- | --- | --- |
| `backgroundColor(String)` / `backgroundColor(int)` | 窗口底色 | `0xF018181C` | 支持 `"#RRGGBB"`、`"#AARRGGBB"`、int ARGB；alpha 为 0 时**不画底色**，但窗口矩形仍然拦截鼠标 |
| `borderColor(String)` / `borderColor(int)` | 边框颜色 | `0xFF000000` | `style("minecraft")` 时忽略 |
| `borderWidth(int)` | 边框粗细 | `1` | 向内绘制；`0` 或负数为无边框；控件贴边时会盖住这 1px |
| `titleBarColor(String)` / `titleBarColor(int)` | 标题栏底色 | `0xFF2D2F38` | `style("minecraft")` 时忽略 |
| `titleColor(String)` / `titleColor(int)` | 标题文字色 | `0xFFFFFFFF` | 一直生效 |
| `dim(int)` | 窗口后面的全屏黑色遮罩 | `0` | 取值 `0~255`（自动截断），0 为关闭 |
| `style(String)` | 界面风格 | `"default"` | 只有 `"default"` 与 `"minecraft"` 两种有实际区别 |
| `font(String)` | 该窗口所有文字的字体 id | `""` | 空 = 客户端默认字体；细节见 4.3 |

颜色只有 setter，没有 getter；需要记录就用你自己的变量。

### 4.1 颜色写法

```java
win.backgroundColor("#18181C");        // 自动补成 0xFF18181C
win.backgroundColor("#F018181C");      // 显式带 alpha
win.backgroundColor(0xF018181C);       // int ARGB，等价写法
win.backgroundColor("#00000000");      // 全透明：不画窗口底
```

### 4.2 窗口没有圆角

`GuiWindow` **没有** `radius(...)` 方法，圆角只能靠铺一层 `Panel` 实现：

```java
GuiWindow win = new GuiWindow("demo_round")
        .titleBar(false)
        .size(300, 180)
        .backgroundColor("#00000000")   // 窗口自身透明
        .borderWidth(0);                // 也不要窗口边框

// 先加底板，后加内容：后添加的控件画在上面
win.addPanel("shell", 0, 0, 300, 180)
        .radius(10)
        .backgroundColor("#F018181C")
        .borderColor("#FF3A4356")
        .borderWidth(1);

win.addLabel("title", 0, 10, "圆角窗口").color("#FFD166").centered(true).widthPercent(100);
win.addButton("ok", 20, 120, 260, 24, "知道了")
        .onClick(event -> api.closeWindow(event.player(), "demo_round"));
```

注意 `Panel` 的 `radius` 是纯视觉的，布局仍然按矩形算；如果这个圆角面板绑了 `onClick`，圆角缺口区域也会被当作面板矩形的一部分而可点。

### 4.3 style

| 值 | 表现 |
| --- | --- |
| `"default"` | 使用你设置的颜色：自定义底色、边框、标题栏色 |
| `"minecraft"` | 香草风格：窗口固定为深色半透明底 + 外黑内白双层边框，标题栏固定色；按钮、输入框、物品格、面板切换为原版配色。此时窗口的 `backgroundColor` / `borderColor` / `borderWidth` / `titleBarColor` 被忽略 |
| 其他字符串 | 等同 `"default"` |

`style("minecraft")` 适合做“看起来像原版”的界面；一旦用了它，就别再指望自定义窗口底色。

### 4.4 font

`font(String)` 接收的是**字体资源 id**，不是字体文件路径：

- `""`（默认）：使用客户端原版字体。
- `"guiapi:sysfont"`：使用 GuiApi 客户端模组自动打包的 Windows 系统字体。具体用哪个字体文件、多大字号，由**客户端**的 `config/guiapi-client.txt` 决定：

```ini
# 客户端配置文件，不是服务端配置
font=simhei.ttf
font_size=10
```

默认会按 `msyh.ttc`（微软雅黑）→ `Deng.ttf` → `simhei.ttf` 的顺序查找，字号默认 9。因此服务端只写 `"guiapi:sysfont"` 即可，不要在这里写“微软雅黑”之类的字体名。
- 其他 id 也可以，但必须由客户端已加载的资源包提供；资源不存在时客户端会自动回退到原版字体，不会报错。

字体是窗口级的：标题、Label、Button、输入框、tooltip 全部生效。

### 4.5 dim 遮罩

`dim(int alpha)` 在**所有窗口的下方**铺一层全屏黑色遮罩，alpha 取 `0~255`：

```java
GuiWindow confirm = new GuiWindow("demo_confirm")
        .size(300, 140)
        .alwaysOnTop(true)
        .dim(150)                 // 半透明压暗背景
        .closeOnEsc(false)
        .onEscape(event -> api.closeWindow(event.player(), "demo_confirm"));
```

- 遮罩的 alpha 由所有已打开窗口中最大的 `dim` 决定，不是每个窗口各画一层。
- 遮罩**不拦截点击**：它只影响画面。下面窗口的控件仍然在原来的位置接收点击。
- 遮罩会铺满整个屏幕，包括窗口之外的区域。
- 窗口关闭后它带来的遮罩也随之消失（没有独立的“全局遮罩”对象）。

## 5. 行为开关

| 方法 | 作用 | 默认 | 注意 |
| --- | --- | --- | --- |
| `fullscreen(boolean)` | 铺满整个虚拟画布 | `false` | 忽略 `position` / `size`；不可拖动；内部要用百分比布局 |
| `draggable(boolean)` | 允许拖标题栏移动窗口 | `true` | 需要标题栏高度 `> 0` |
| `alwaysOnTop(boolean)` | 始终压在其他窗口之上 | `false` | 点击它下面的窗口不会把下面的窗口抬到它上面；适合确认框、提示条 |
| `closeOnEsc(boolean)` | Esc 是否直接关闭 | `true` | `false` 时改为向服务端发 `esc` 事件（见 5.1） |
| `onEscape(Consumer<GuiActionEvent>)` | 接收 `esc` 事件 | 无 | 只在 `closeOnEsc(false)` 时有意义 |
| `alwaysOnTop()` / `closeOnEsc()` | 读回开关 | — | — |

### 5.1 Esc 与关闭按钮的真实语义

| 情况 | 结果 |
| --- | --- |
| 默认（`closeOnEsc = true`）按 Esc | 客户端退出整个 Gui 屏幕，**该玩家所有 GuiApi 窗口都会关闭**（不是只关最上层） |
| `closeOnEsc = false` 按 Esc | 只有**最上层**窗口收到 `esc` 事件；窗口不关闭，服务端自己决定怎么做 |
| 点标题栏 ×，`closeOnEsc = true` | 只关这一个窗口 |
| 点标题栏 ×，`closeOnEsc = false` | 不发关闭，改为发 `esc` 事件；窗口保持打开 |
| 有输入框正在输入时按 Esc | 先把输入内容提交给服务端，窗口不会关闭 |

`esc` 事件的 `GuiActionEvent` 中：`window()` 是窗口，`widget()` 为 `null`，`action()` 为 `"esc"`。所以回调里不要直接调用 `event.widget().id()`。

```java
GuiWindow win = new GuiWindow("demo_esc")
        .size(280, 150)
        .closeOnEsc(false)
        .onEscape(event -> {
            // 玩家按了 Esc 或点了 ×：这里选择关闭，也可以换成"弹确认框"
            api.closeWindow(event.player(), "demo_esc");
        });
```

**如果 `closeOnEsc(false)` 又没有写 `onEscape`，玩家就无法关闭这个窗口**（只能等你自己关或重连），务必成对使用。

## 6. 控件坐标规则

### 6.1 原点

控件坐标的原点是**内容区左上角**：

- 有标题栏：原点在窗口顶部下方 `titleHeight` 处。
- 无标题栏：原点就是窗口左上角。

```java
win.addLabel("a", 0, 0, "我会紧贴标题栏下方");
```

### 6.2 最终位置公式

设：`winW` = 窗口宽，`winH` = 窗口高，`titleH` = 标题栏高，`contentH = winH - titleH`。
下表是客户端实际使用的换算规则（`x`、`y`、`w`、`h` 都是你在 `addXxx` / `position` / `size` 里写的值）：

| 维度 | 有百分比 | 无百分比，值为负 | 无百分比，值为非负 |
| --- | --- | --- | --- |
| 横坐标 | `winW × xPercent / 100 + x` | `winW / 2 + x`（以窗口中心为基准偏移） | `x` |
| 纵坐标 | `contentH × yPercent / 100 + y` | `contentH / 2 + y`（以内容区中心为基准偏移） | `y` |
| 宽度 | `winW × widthPercent / 100 + w` | `winW - x + w`，即**右边缘留 `abs(w)`** | `w` |
| 高度 | `contentH × heightPercent / 100 + h` | `contentH - y + h`，即**底边留 `abs(h)`** | `h` |

高度还有一条**优先级最高的规则**：只要设置过 `aspect(...)`，高度就完全由 `宽度 / aspect` 决定，`heightPercent` 和 `h` 都不再生效。

### 6.3 负值的三种含义（最容易混）

| 写法 | 含义 | 例子 |
| --- | --- | --- |
| 无百分比 + `x < 0` | 相对窗口水平中心偏移 | `x = -16, w = 32` → 水平居中 |
| 无百分比 + `y < 0` | 相对内容区垂直中心偏移 | `y = -10, h = 20` → 垂直居中 |
| 有百分比 + `x < 0` | 只是叠加的像素偏移，**不再居中** | `xPercent(100) + x = -80` → 贴右边 |
| `w < 0` | 弹性宽度：右边缘固定，宽度随窗口变化 | `x = 20, w = -20` → 左右各留 20 |
| `h < 0` | 弹性高度：下边缘固定 | `y = 40, h = -20` → 底部留 20 |

### 6.4 控件默认尺寸

| 控件 | 高度 | 布局提示 |
| --- | --- | --- |
| Label | 9（构造时） | 实际行高约 10px；设置正宽度后会自动换行，宽度也参与命中/裁剪 |
| Button | 你指定 | 常用 20~24，太矮文字挤 |
| Panel | 你指定 | 高度为 0 时不可见 |
| ImageWidget | 你指定 | 高度为 0 时不可见 |
| ItemWidget | 你指定 | 图标按 `min(w,h)/18` 放大（1~4 倍） |
| TextField | 你指定 | 常用 20~24 |
| Slider | 20（固定） | 轨道在 `y+12 ~ y+16`，可点区域约 `y+6 ~ y+20` |
| Checkbox | 12（固定） | 方框 12×12 + 右侧文字；可点区域约 `16 + 文字宽` |
| Radio | 12（固定） | 与 Checkbox 相同 |
| Dropdown | 18（固定） | 展开列表向下最多显示 6 项，每项 16px |

### 6.5 裁剪

控件超出**窗口矩形**的部分会被裁掉：

- 不绘制、不响应 hover、不响应点击。
- 半截在窗口外的按钮，露出的部分能点，被裁掉的部分点不到。
- Label 的换行文本会按行往下排，超出窗口的行直接看不见，不会把窗口撑高。

## 7. 百分比布局

### 7.1 四个方法

| 方法 | 相对谁 | 说明 |
| --- | --- | --- |
| `xPercent(double)` | **窗口宽** | 最终横坐标 = `winW × pct / 100 + x` |
| `yPercent(double)` | **内容区高** | 最终纵坐标 = `contentH × pct / 100 + y` |
| `widthPercent(double)` | **窗口宽** | 最终宽 = `winW × pct / 100 + w` |
| `heightPercent(double)` | **内容区高** | 最终高 = `contentH × pct / 100 + h` |

四个方法都返回 `Widget`，可以直接接在控件专属方法之后：

```java
win.addPanel("sidebar", 0, 0, 0, 0)
        .borderWidth(0)
        .backgroundColor("#FF1B1F27")
        .widthPercent(18)
        .heightPercent(100);       // 注意：100% 高度 = 内容区高度，不是窗口高度
```

### 7.2 百分比与像素的混用规则

1. **百分比决定基准，像素只做微调。** 例如 `xPercent(4)` + `x = 8` 表示“窗口宽的 4% 再加 8px”。
2. **同一轴不要同时写死两种基准。** 大结构用百分比，内边距、按钮高度这类小尺寸用像素。
3. **`100% + 负偏移` 是最常用的右/下对齐写法：**

```java
Button right = win.addButton("right", -92, 8, 80, 20, "靠右"); // 宽 80，右留 12
right.xPercent(100);   // 基准到窗口右边缘，再减 92 => 右边距 12

Button bottom = win.addButton("bottom", 20, -44, 120, 24, "靠下");
bottom.yPercent(100);  // 基准到内容区底边，再减 44 => 底边距 20
```

4. **`widthPercent(100)` 配 `heightPercent(100)` 才是铺满内容区**；只写宽度时高度保持你传入的值，传 0 就看不见。
5. **`xPercent(50)` 不是居中**，它把控件**左边缘**放在窗口正中。真居中要再减半个宽度：

```java
Button center = win.addButton("center", -60, 40, 120, 22, "居中");
center.xPercent(50);   // 左边缘在 50%，再减 60 => 正好居中
```

6. 窗口自身不支持百分比尺寸。响应式界面请用 `fullscreen(true)`，再用百分比排内部控件。

### 7.3 三种“居中”的区别

| 目标 | 写法 |
| --- | --- |
| 窗口在屏幕上居中 | `position(-1, -1)` |
| 一行文字在**整个窗口**水平居中 | `label.centered(true)` 且**不设宽度**（Label 默认宽 0），此时 `x` 被忽略 |
| 文字在**自己的盒子**里居中（如卡片标题） | `label.centered(true)` + `widthPercent(卡片宽)` + `xPercent(卡片左边缘)` |
| 固定宽控件水平居中 | `xPercent(50)` + `x = -宽度/2` |
| 窗口内任意控件垂直居中 | `yPercent(50)` + `y = -高度/2` |

## 8. 高度百分比换算（重点）

### 8.1 为什么需要换算

`widthPercent` 和 `heightPercent` 的基数不同（窗口宽 vs 内容区高），画布也不是正方形。所以“宽度 20%、希望图片不变形”不能直接写 `heightPercent(20)`。要让一个宽高比为 `aspect` 的图片/卡片在百分比布局下**等高等比**，高度百分比必须按下面的公式算。

### 8.2 通用公式

```text
高度百分比 = 宽度百分比 / 100 × 参考宽度 / aspect / 参考高度 × 100

aspect   = 图片宽 / 图片高（宽除以高）
参考宽度 = 百分比所相对的宽度：普通窗口填窗口宽度；fullscreen 填虚拟画布宽度
参考高度 = 内容区高度：窗口高 − 标题栏高度（默认 16）；fullscreen 填虚拟画布高 − 标题栏高度
```

**不要盲目套用 `× 640 ÷ 430`**：`widthPercent` / `heightPercent` 的基数是**当前窗口**（fullscreen 时是当前虚拟画布），不是固定的 640×430 设计稿。很多地方流传的 `高度百分比 = 宽度百分比 × 1.4884 ÷ aspect` 只在「窗口恰好是 640×430 且没有标题栏」时成立。

### 8.3 推导

设宽度百分比为 `W`，目标图片宽高比为 `aspect`，窗口宽 `BW`，内容区高 `BH`。

1. 宽度像素：`W / 100 × BW`
2. 等比高度像素：`宽度像素 / aspect`
3. 高度百分比：`高度像素 / BH × 100`

代入：

```text
H = (W / 100 × BW / aspect) / BH × 100
  = W / 100 × BW / aspect / BH × 100
```

### 8.4 例子（按 640×430 全屏窗口、隐藏标题栏计算）

| 场景 | 宽度百分比 | aspect = 宽/高 | 高度百分比 |
| --- | --- | --- | --- |
| 160×225 竖版卡牌 | 20 | `160.0 / 225.0 ≈ 0.711` | `20 × 1.4884 / 0.711 ≈ 41.9` |
| 16:9 背景图 | 100 | `1.778` | `100 × 1.4884 / 1.778 ≈ 83.7` |
| 1:1 头像 | 8 | `1.0` | `8 × 1.4884 ≈ 11.9` |
| 156×44 名牌底图 | 13 | `156.0 / 44.0 ≈ 3.545` | `13 × 1.4884 / 3.545 ≈ 5.5` |

手算校验（第一行）：20% × 640 = 128px 宽；128 / 0.711 = 180px 高；180 / 430 = 41.9%。

换成别的窗口尺寸时，把上面的 640 / 430 换成该窗口的宽度与内容区高度，等比关系同样成立。

### 8.5 工具方法

```java
/**
 * 把"宽度百分比"换算成等高等比的"高度百分比"。
 *
 * @param widthPercent 目标宽度百分比，例如 20 表示窗口宽的 20%
 * @param aspect       原图宽高比 = 宽 / 高，例如 160×225 的卡牌传 160.0 / 225.0
 * @param windowWidth  百分比所相对的宽度：普通窗口填窗口宽；fullscreen 填虚拟画布宽
 * @param contentHeight 内容区高度：窗口高 − 标题栏高（fullscreen 同理）
 * @return 对应的高度百分比
 */
public static double pctHeight(double widthPercent, double aspect,
                               double windowWidth, double contentHeight) {
    if (aspect <= 0) {
        throw new IllegalArgumentException("aspect 必须大于 0");
    }
    return widthPercent / 100.0 * windowWidth / aspect / contentHeight * 100.0;
}
```

用法（假设窗口为 640×430、有 16px 标题栏）：

```java
double cardAspect = 160.0 / 225.0;
double cardW = 20;

win.addImage("card", 0, 0, 0, 0, "card_art")
        .fit("cover")
        .widthPercent(cardW)
        .heightPercent(pctHeight(cardW, cardAspect, 640, 430 - 16))
        .xPercent(4)
        .yPercent(18);
```

### 8.6 使用前提（务必理解）

1. **`heightPercent` 的基数是内容区高度**（窗口高 − 标题栏高），不是整个窗口高度。默认标题栏 16px，计算时要扣除。
2. **不要写死 640 / 430**：虚拟画布取决于玩家分辨率与 GUI 缩放，屏幕够大时画布远大于 640×430。写死这两个数只在你确实创建了 `size(640, 430)` 的窗口时才准确。
3. 不想做任何换算、也不想关心画布大小时，直接用下面的 `aspect()`。

### 8.7 更推荐的替代：aspect()

`aspect(double widthOverHeight)` 让客户端**直接按解析出来的宽度算高度**，与画布比例、标题栏都无关，任何分辨率都严格不变形：

```java
win.addImage("avatar", 0, 0, 0, 0, "avatar_" + player.getName())
        .fit("cover")
        .widthPercent(8)
        .aspect(1.0)            // 1:1 头像，高度自动 = 宽度
        .xPercent(6)
        .yPercent(10);

win.addImage("card", 0, 0, 0, 0, "card_art")
        .fit("cover")
        .widthPercent(20)
        .aspect(160.0 / 225.0)  // 160×225 卡牌，高度自动等比
        .xPercent(20)
        .yPercent(18);
```

选择建议：

| 需求 | 用什么 |
| --- | --- |
| 图片、卡牌、头像等必须不变形 | `widthPercent(...) + aspect(宽/高)` |
| 需要一个“显式高度百分比”，或要和别的百分比面板对齐 | `pctHeight(...)`，并接受 8.6 的两条误差 |
| 同时写了 `aspect` 和 `heightPercent` | `aspect` 生效，`heightPercent` 被忽略 |

## 9. 绘制与命中顺序

| 规则 | 说明 |
| --- | --- |
| 窗口层级 | 新打开的窗口在最上面；`alwaysOnTop(true)` 的窗口永远在所有普通窗口之上；点击某个窗口会把它提到最前（置顶窗口不会被压下去） |
| 同 id 重开 | 替换内容，并提到最前 |
| 控件绘制顺序 | 按 `addXxx` 的调用顺序绘制，**后加的画在上面** |
| 同 id 控件 | 覆盖旧控件，绘制位置保持第一次添加时的顺序 |
| 点击命中 | 从**先添加**的控件开始遍历，第一个“可点击且命中”的控件吃掉点击；Label 和未设 `onClick` 的 Panel 不拦截点击 |
| 可点击条件 | Button/TextField/ItemWidget 整个矩形可点；Panel/Image 需要设 `onClick` 才可点；Checkbox/Radio 的可点区域是方框加文字宽度；Slider 只有轨道附近一条；Dropdown 是其 18px 高的盒 |
| 窗口背景 | 点击窗口内没有控件的空白处会被窗口吞掉，不会穿透到游戏或下面的窗口 |
| 裁剪 | 超出窗口矩形不画也不可点（下拉展开列表例外，见 04 章） |

两个直接后果：

1. **两个可点击控件重叠时，画在上面的那个不一定能点到**，因为命中按添加顺序、先添加者优先。做“图片 + 透明点击层”时，把图片先加、点击层后加，并确保图片本身没有绑 `onClick`，否则图片会先吃掉点击。
2. **视觉层级与命中层级可能相反**，排查“按钮点不动”时先看它下面是否压着一个更早添加的可点击控件。

## 10. 完整示例：响应式卡片页

下面这个类展示：全屏窗口、无标题栏、铺满的背景、按百分比排列的两张卡牌、用 `pctHeight` 保证卡牌等比、以及底部按钮。可以直接放进你的插件里调用 `new ResponsivePage(api).open(player)`。

```java
package com.example.mygui;

import com.guiapi.paper.GuiApi;
import com.guiapi.paper.GuiWindow;
import com.guiapi.paper.widget.Button;
import org.bukkit.entity.Player;

public final class ResponsivePage {
    private final GuiApi api;

    public ResponsivePage(GuiApi api) {
        this.api = api;
    }

    /** 按 640×430 设计基准估算高度百分比；画布更大时会有偏差，精确等比请直接改用 aspect()。 */
    public static double pctHeight(double widthPercent, double aspect) {
        if (aspect <= 0) {
            throw new IllegalArgumentException("aspect 必须大于 0");
        }
        return widthPercent / 100.0 * 640.0 / aspect / 430.0 * 100.0;
    }

    public void open(Player player) {
        GuiWindow win = new GuiWindow("demo_responsive")
                .fullscreen(true)
                .titleBar(false)
                .backgroundColor("#00000000")
                .borderWidth(0);

        // 1. 铺满整个内容区的底板（全屏 + 无标题栏 => 内容区 = 整个画布）
        win.addPanel("backdrop", 0, 0, 0, 0)
                .borderWidth(0)
                .backgroundColor("#F0121418")
                .widthPercent(100)
                .heightPercent(100);

        // 2. 顶部标题：宽度 100% + 盒内居中
        win.addLabel("title", 0, 0, "响应式卡片页")
                .color("#FFD166")
                .scale(1.6f)
                .centered(true)
                .widthPercent(100)
                .yPercent(7);

        // 3. 两张 160×225 的卡牌：宽度 22%，高度用公式换算
        double cardAspect = 160.0 / 225.0;
        double cardW = 22;
        double cardH = pctHeight(cardW, cardAspect);

        for (int i = 0; i < 2; i++) {
            double x = 8 + i * 26;

            win.addPanel("cardBg" + i, 0, 0, 0, 0)
                    .radius(8)
                    .backgroundColor("#FF232936")
                    .borderColor("#FF3A4356")
                    .borderWidth(1)
                    .widthPercent(cardW)
                    .heightPercent(cardH)
                    .xPercent(x)
                    .yPercent(18);

            win.addLabel("cardTitle" + i, 0, 0, "卡牌 " + (i + 1))
                    .color("#FFFFFFFF")
                    .centered(true)
                    .widthPercent(cardW)
                    .xPercent(x)
                    .yPercent(18 + cardH - 8);
        }

        // 4. 底部关闭按钮：左边缘 42%，宽 16%
        Button close = win.addButton("close", 0, 0, 0, 24, "关闭");
        close.widthPercent(16);
        close.xPercent(42);
        close.yPercent(86);
        close.onClick(event -> api.closeWindow(event.player(), "demo_responsive"));

        api.openWindow(player, win);
    }
}
```

如果这两张卡要显示图片并**绝对**保证不变形，把上面循环里的 `addPanel` 换成等价写法（`i`、`x`、`cardW`、`cardAspect` 都沿用循环里的变量）：

```java
win.addImage("cardArt" + i, 0, 0, 0, 0, "card_art")
        .fit("cover")
        .widthPercent(cardW)
        .aspect(cardAspect)      // 高度 = 宽度 / aspect，不受画布比例影响
        .xPercent(x)
        .yPercent(18);
```

## 11. 常见坑清单

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 全屏页面控件全挤在左上角 | 忘了 `fullscreen(true)`，窗口仍是 260×160 | 全屏 + 百分比 |
| 面板/图片完全看不见 | 只设了 `widthPercent`，高度仍是 0 | 同时设 `heightPercent` 或用 `aspect` |
| 改了 `position()` 但窗口没移动 | 同 id 重开保留了玩家拖动后的位置 | 先 `closeWindow` 再开，或 `draggable(false)` |
| 控件比预期高/矮一点 | 高度百分比基数是不含标题栏的内容区 | 见第 8 节；或直接用 `aspect` |
| 图片被拉变形 | 用了 `widthPercent + heightPercent` 但比例不匹配 | 改用 `aspect(宽/高)` |
| 百分比铺满后右侧/底部有缝 | `xPercent` 相对窗口宽，`yPercent` 相对内容区高，混用 100% 会错位 | 分别按各自的基数计算 |
| 按钮点不动 | 被更早添加的可点击控件压住；或按钮超出窗口被裁剪 | 调整添加顺序，检查坐标 |
| 透明窗口挡住了游戏点击 | alpha=0 只是不画底色，窗口矩形仍然拦截鼠标 | 需要“看得见但点得到下面”的界面时，缩小窗口范围或关闭窗口 |
| Esc 一按整页都没了 | 默认 `closeOnEsc = true` 会关闭该玩家全部窗口 | 需要保留页面时设 `closeOnEsc(false)` 并处理 `onEscape` |
| `closeOnEsc(false)` 后关不掉 | 没写 `onEscape`，× 也只发 esc 事件 | 在 `onEscape` 里调用 `closeWindow` |
| 标题栏没有 × | `titleBar(false)` 或 `titleHeight < 14` | 自备关闭按钮，或把标题栏高度调到 `>= 14` |
| 窗口 ID 写错，更新无效 | `updateWidget` 的窗口 id/控件 id 必须逐字一致 | 用常量保存 id，避免手写字符串 |
