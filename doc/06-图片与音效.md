# 06 图片与音效

> 读者：已经能打开窗口、添加控件的第三方开发者。
> 前置阅读：[01-快速开始](01-快速开始.md)、[02-窗口与坐标](02-窗口与坐标.md)、[03-基础控件](03-基础控件.md)。
> 相关阅读：[05-事件与交互](05-事件与交互.md)、[08-布局技巧与常见问题](08-布局技巧与常见问题.md)、[09-实战案例](09-实战案例.md)。

GuiApi 的资源只有两类：**图片**和**音效**。两者都用字符串 id 引用，服务端注册一次，客户端按需接收并缓存。插件不需要给玩家发资源包，也不需要手动改 `sounds.json`。

---

## 6.1 资源生命周期

1. 在 `onEnable()` 里注册图片 / 音效，全服一次即可，不要每个玩家注册一遍。
2. 打开窗口或播放音效时，客户端**自动**收到尚未收到过的资源。
3. 客户端按 id 缓存：同一版本只收一次，重复 `openWindow` / `playSound` 不再传输。
4. 资源内容更新后，重新注册同一个 id 并强制重发，或重新打开窗口，客户端才会换新。

| 触发动作 | 会不会向客户端传资源 |
| --- | --- |
| `openWindow` 且窗口里有 `ImageWidget` | 只传该玩家还没收到当前版本的图片 |
| `playSound` / `playLoopingSound` | 只传该玩家还没收到当前版本的音效 |
| `preloadImage` / `preloadSound` | 同上，用于提前预热 |
| `sendImage` | 无条件重传当前图片 |
| `updateWidget(..., "image", 新id)` | **不传图**，只改控件引用；新图必须已经下发过 |

---

## 6.2 图片

### 6.2.1 方法

| 签名 | 作用 | 参数 | 注意 |
| --- | --- | --- | --- |
| `void registerImage(String imageId, byte[] bytes)` | 把一个图片注册到全局表，供 `ImageWidget` 引用 | `imageId` 全局唯一；`bytes` 为图片文件字节 | 可重复调用覆盖；每次调用都会让该 id 的版本 +1，已在线玩家下次打开窗口会重新收到 |
| `void preloadImage(Player player, String imageId)` | 给某个玩家预热一张图 | 玩家、已注册的 id | 只在该玩家还没收到当前版本时发送；适合头像、卡面这类稍后才通过 `updateWidget` 出现的图 |
| `void sendImage(Player player, String imageId)` | 强制把当前图片重发给玩家 | 玩家、已注册的 id | 图片字节变了（例如运行时生成头像）时用；未注册的 id 会被静默忽略 |

补充行为：

- `openWindow` 会遍历窗口里的所有 `ImageWidget`，按需下发它们引用的图片。窗口里已有的图不需要手动 `preloadImage`。
- 客户端**同一版本只收一次**。玩家重新登录 / 客户端重新握手时缓存重置，服务端会重新下发。
- 关闭窗口不会清掉客户端已收到的图片，下次打开同一张图不再传输。
- 图片 id 区分大小写且全局共享。多个插件共存时建议统一加前缀，例如 `kitten_card_bomb`、`menu_icon_shop`。

### 6.2.2 注册

```java
import com.guiapi.paper.GuiApi;

import java.io.IOException;
import java.io.InputStream;

public final class AssetsDemo {

    private final GuiApi api = GuiApi.get();
    private final org.bukkit.plugin.java.JavaPlugin plugin;

    public AssetsDemo(org.bukkit.plugin.java.JavaPlugin plugin) {
        this.plugin = plugin;
    }

    /** 从插件 jar 的 assets/demo/card_skip.png 读取并注册。 */
    public void registerCard() {
        byte[] png = read("assets/demo/card_skip.png");
        if (png.length == 0) return;          // 资源缺失时不要注册空字节
        api.registerImage("demo_card_skip", png);
    }

    private byte[] read(String path) {
        try (InputStream in = plugin.getResource(path)) {
            return in == null ? new byte[0] : in.readAllBytes();
        } catch (IOException e) {
            plugin.getLogger().warning("读取资源失败: " + path);
            return new byte[0];
        }
    }
}
```

**格式说明**：`registerImage` 的入参可以是 PNG / JPEG 字节，但当前客户端使用 Minecraft 原生图片解码，**只稳定支持 PNG**。JPEG 会解码失败，界面上是空白框，客户端日志里会出现 `could not be decoded`。素材请统一转成 PNG。

### 6.2.3 在窗口里使用

```java
import com.guiapi.paper.GuiApi;
import com.guiapi.paper.GuiWindow;
import org.bukkit.entity.Player;

GuiApi api = GuiApi.get();

GuiWindow window = new GuiWindow("demo_hand")
        .fullscreen(true)
        .titleBar(false)
        .backgroundColor("#00000000")
        .borderWidth(0);

// 卡牌：宽度 12%，aspect 用素材原始宽高比，位置用百分比
window.addImage("card0", 0, 0, 0, 0, "demo_card_skip")
        .fit("contain")
        .onClick(event -> api.playSound(event.player(), "demo_click", 0.8f, 1.0f))
        .widthPercent(12)
        .aspect(160.0 / 225.0)
        .xPercent(44)
        .yPercent(40);

api.openWindow(player, window);
```

`fit` 的取值（`ImageWidget.fit`）：

| 值 | 效果 | 典型用途 |
| --- | --- | --- |
| `stretch`（默认） | 拉伸填满控件框，会变形 | 纯色底、渐变占位 |
| `cover` | 等比放大填满，超出部分裁掉 | 全屏背景、封面 |
| `contain` | 等比缩小到完整显示，留黑边 | 卡牌、图标、按钮图 |

链式调用注意：`widthPercent` / `aspect` / `xPercent` 返回的是基类 `Widget`，调用之后就不能再接 `fit`、`onClick` 这类图片控件专属方法。**专属方法写在前面**，详见 [08-布局技巧与常见问题](08-布局技巧与常见问题.md)。

### 6.2.4 运行时换图

用 `updateWidget` 改 `image` 属性即可，不会重新发送整个窗口：

```java
// 头像下载完成：先把新图送到客户端，再让控件引用它
api.preloadImage(player, "demo_avatar_steve");
api.updateWidget(player, "demo_lobby", "avatar0",
        java.util.Map.of("image", "demo_avatar_steve", "visible", true));
```

如果同一 id 的图片内容变了（例如重新生成头像），需要重注册并强推：

```java
api.registerImage("demo_avatar_steve", newBytes);  // 版本 +1
api.sendImage(player, "demo_avatar_steve");          // 立即发当前字节
api.updateWidget(player, "demo_lobby", "avatar0", java.util.Map.of("image", "demo_avatar_steve"));
```

`updateWidget` 只有在窗口当前确实打开时才会生效；窗口已关闭时客户端会忽略这条更新，详见 [05-事件与交互](05-事件与交互.md)。

### 6.2.5 图片不显示的排查

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 控件位置正确但一片空白 | 图片没有注册，或注册时传了空字节 | 检查 `registerImage` 是否在 `onEnable` 执行、资源路径是否正确 |
| 只有部分玩家看不到 | 玩家打开窗口时图片还没注册完；或 id 拼写不一致 | id 大小写完全一致；注册放在 `onEnable`，不要延迟到开窗前才注册 |
| 换了图还是旧的 | 只调了 `registerImage` 没有重新打开窗口 / 没有 `sendImage` | 重新注册 + `sendImage`，或用新 id |
| `updateWidget` 换图无效 | 属性名写成了 `imageId` / 图从未下发 | 属性名是 `image`；换图前 `preloadImage` |
| 图片被拉伸变形 | `fit` 为默认的 `stretch` | 卡牌用 `contain`，背景用 `cover` |
| JPEG 显示空白 | 客户端只稳定解码 PNG | 素材统一转 PNG |

## 6.3 音效

### 6.3.1 方法

| 签名 | 作用 | 参数 | 注意 |
| --- | --- | --- | --- |
| `void registerSound(String soundId, byte[] oggBytes)` | 注册音效 | `soundId` 全局唯一；`oggBytes` 为 **OGG** 文件字节 | 只支持 OGG；MP3/WAV 必须先转码 |
| `void preloadSound(Player player, String soundId)` | 给玩家预热音效 | 玩家、已注册 id | 用于登录 / 开局时一次性送达，避免第一次播放延迟 |
| `void playSound(Player player, String soundId)` | 以默认音量 1.0、音调 1.0 播一次 | 玩家、id | 等价于 `playSound(player, id, 1.0f, 1.0f)` |
| `void playSound(Player player, String soundId, float volume, float pitch)` | 播放一次，可调音量与音调 | `volume` 常用 0~1；`pitch` 1.0 为原调 | 未注册的 id 不会发声 |
| `void playLoopingSound(Player player, String soundId, float volume)` | 循环播放 | 玩家、id、音量 | 同一 id 再次循环会替换旧循环；`stopSound` 停止 |
| `void setLoopingSoundVolume(Player player, String soundId, float volume)` | 实时修改循环音的音量 | 玩家、id、新音量（<0 按 0） | 不会从头重播；客户端 1.3.13+ 支持，更旧客户端会忽略 |
| `void stopSound(Player player, String soundId)` | 停止该 id 的循环音 | 玩家、id | 一次性音效也可能被同一 id 的停止一并掐掉 |
| `void stopAllSounds(Player player)` | 停止该玩家所有循环音 / 活动音效 | 玩家 | 离开牌局、死亡、退出时收尾 |
| `void setClickSound(String soundId, float volume)` | 设置**全局默认**点击音 | 已注册 id、音量；`null` 关闭 | 所有插件共享，会影响同服其他界面；推荐用窗口级 `clickSound` |
| `GuiWindow clickSound(String soundId, float volume)` | 设置**本窗口**的点击音 | 已注册 id、音量；`null` 表示本窗口静音 | 优先级高于全局设置，只影响该窗口 |

### 6.3.2 只能 OGG，且走主音量

- 客户端把音效放进自己生成的资源包播放，**只有 OGG（Vorbis）能被识别**。WAV、MP3 直接注册不会报错，但玩家永远听不到。转码示例：`ffmpeg -i click.mp3 -c:a libvorbis -q:a 5 click.ogg`。
- 所有音效统一走客户端的 **MASTER（主音量）** 通道。玩家在游戏设置里把主音量拉到 0，所有 GUI 音效都会一起静音；客户端模组没有独立的音量开关，音量完全由方法里的 `volume` 参数决定。
- 音调低于 0.1 会被客户端抬到 0.1；音量低于 0 会被当作 0。

### 6.3.3 注册与播放

```java
import com.guiapi.paper.GuiApi;
import org.bukkit.entity.Player;

GuiApi api = GuiApi.get();

// onEnable 中：
api.registerSound("demo_click", clickOgg);
api.registerSound("demo_bgm", bgmOgg);

// 玩家登录 / 开局时预热，避免第一次播放要等资源装好
api.preloadSound(player, "demo_click");
api.preloadSound(player, "demo_bgm");

// 一次性音效
api.playSound(player, "demo_click", 0.8f, 1.0f);

// 循环 BGM
api.playLoopingSound(player, "demo_bgm", 0.55f);

// 实时压低 / 恢复（例如有人开麦时）
api.setLoopingSoundVolume(player, "demo_bgm", 0.0f);
api.setLoopingSoundVolume(player, "demo_bgm", 0.55f);

// 离开时停止
api.stopSound(player, "demo_bgm");
```

关于 id：同一个 id 注册一次即可；`playSound` 会自动把还没送达的音效发给该玩家。**音效和窗口生命周期无关**：`closeWindow` 不会停止 BGM，必须显式 `stopSound` 或 `stopAllSounds`。

### 6.3.4 循环音的几个细节

| 场景 | 行为 |
| --- | --- |
| 对同一玩家、同一 id 再次 `playLoopingSound` | 旧循环被替换，从头开始 |
| 循环中途改音量 | 用 `setLoopingSoundVolume`，不重启；`playLoopingSound` 重新调用会重启 |
| 循环中途要改音调 | 不支持实时改音调，只能停止后用 `playSound`/`playLoopingSound` 重播 |
| 一次性音效重叠 | 同一 id 可以同时响多次；不需要手动管理 |
| 循环音持续到窗口关闭后 | 会继续响，必须 `stopSound` |

### 6.3.5 点击音

推荐**按窗口设置**，这样插件之间的界面互不影响：

```java
// 只让这个窗口的按钮有点击音
GuiWindow window = new GuiWindow("shop").title("商店").size(240, 160)
        .clickSound("demo_click", 0.7f);

// 同一个插件里不想出声的窗口：显式静音
GuiWindow hud = new GuiWindow("hud")
        .clickSound(null, 0f);
```

- 规则是「**窗口优先，全局兜底**」：窗口调用过 `clickSound(...)` 就只用窗口的配置（包括 `null` 静音）；没调用过才回落到 `api.setClickSound(...)`。
- `api.setClickSound(...)` 是全局设置，`GuiApi` 是**所有插件共享的单例**，一旦设置，同服其他插件的界面也会跟着响。除非你的服务器只有一套 GUI，否则建议不用，或只在确实需要统一音效时使用。
- 点击音由服务端在收到控件的 `click` 事件时播放，**只有按钮、可点击图片、可点击 Panel、物品控件会产生 `click`**；没有 `onClick` 的图片 / Panel 不会上报点击。
- 滑块 `change`、滚动条 `change`、勾选框 `toggle`、下拉 `select`、输入框 `text` 不属于 `click`，不会触发点击音；需要时在各自回调里手动 `playSound`。
- 点击音在插件自己的 `onClick` 之前播放，不占用回调逻辑。

排查「我明明没设音效，别的插件界面却有声」：检查是否有插件在 `onEnable` 里调用了 `api.setClickSound(...)`；改成窗口级 `clickSound` 即可隔离。

### 6.3.6 首次播放的延迟

客户端第一次收到一批新音效时，需要安装音效资源并重载一次游戏资源，可能有 1~2 秒延迟。表现为：第一次点按钮没声，之后再点正常。

建议：

- 在玩家登录、进入大厅、开局前用 `preloadSound` 把所有会用到的音效先送过去；
- 不要在“点击后立即需要有反馈”的路径上才第一次注册音效；
- 图片在资源重载后会自动恢复，不需要因为音效预热而重新 `sendImage`。

### 6.3.7 音效排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 完全没声音 | 文件不是 OGG；id 未注册；玩家主音量为 0 | 转 OGG；检查 `registerSound`；让玩家调主音量 |
| 第一次没声，之后正常 | 音效资源首次安装 / 重载 | 提前 `preloadSound` |
| 循环只响一遍 | 用了 `playSound` 而不是 `playLoopingSound` | 改用循环方法 |
| 改音量后音乐从头开始 | 用 `playLoopingSound` 重播来“改音量” | 改用 `setLoopingSoundVolume` |
| `setLoopingSoundVolume` 无效 | 该 id 当前没有循环；客户端版本低于 1.3.13 | 先 `playLoopingSound`；旧客户端用 `stopSound` + 重新循环 |
| 关掉界面 BGM 还在放 | 音效不随窗口关闭而停止 | 关闭 / 离开时 `stopSound` 或 `stopAllSounds` |
| 点击按钮没有点击音 | 该控件不是 `click` 事件；音效未注册；窗口和全局都没设置 | 检查控件类型；确认 `registerSound`；给窗口加 `clickSound(...)` |
| 自己的界面没设音效却有声音 | 同服某个插件调用了全局 `setClickSound` | 改用窗口级 `clickSound`（含 `null` 静音） |

## 6.4 资源读取与命名

图片、音效都应打进插件 jar，用 `JavaPlugin#getResource` 读取，不要依赖服务器目录里的散文件。

```java
private byte[] load(String path) {
    try (InputStream in = getResource(path)) {
        if (in == null) {
            getLogger().warning("缺少资源: " + path);
            return new byte[0];
        }
        return in.readAllBytes();
    } catch (IOException e) {
        getLogger().warning("读取资源失败: " + path + " (" + e.getMessage() + ")");
        return new byte[0];
    }
}
```

推荐目录：

```
src/main/resources/
  assets/demo/card_skip.png
  assets/demo/click.ogg
  assets/demo/bgm.ogg
```

命名建议：

- 图片和音效 id 都加插件前缀，例如 `demo_`；
- id 只用小写字母、数字、下划线；
- 同一个素材只保留一个 id，不要把同一张图注册成十个名字；
- 注册放在 `onEnable()`，而不是每次开窗时重复注册（重复注册会让版本号增加，导致重复传输）。

## 6.5 收尾清单

- [ ] 图片素材是 PNG，音效素材是 OGG。
- [ ] 所有 `registerImage` / `registerSound` 在 `onEnable` 执行且只执行一次。
- [ ] 玩家登录 / 开局时对常用资源做了 `preload`。
- [ ] 离开牌局、退出登录时停止循环音。
- [ ] 运行时只在图片内容真的变化时才重新 `registerImage` + `sendImage`。
- [ ] 通过 `updateWidget` 换图前，确认新图已经下发。
- [ ] 点击音只注册一次，且知道它只覆盖 `click` 事件。
